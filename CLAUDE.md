# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

AI StockTrader is a mock-trading web app: a single Next.js 16 (App Router) app in TypeScript, with pages and API route handlers in one project, backed by PostgreSQL, with sign-in through Clerk; each user has their own account. Stock prices and news come from Alpha Vantage; buy/sell rankings and per-ticker analysis come from OpenAI (`gpt-6-luna`, reasoning off): the rankings from news sentiment, and each ticker's structured analysis from its news plus computed technicals, its earnings against estimates, estimate revisions and next report date, and its valuation and analyst consensus. The prompts ask for the likely price effect over the horizon (results against expectations, what's already priced in), not the tone of the news. A ticker only appears in a ranking when its own analysis agrees. Every fresh verdict is logged (`verdict_log`) and scored later against SPY (`GET /api/analysis/track-record`).

## Commands

From the repo root:

- `npm install`: install dependencies
- `npm run dev`: dev server on http://localhost:3000 (pages and `/api/*`; Turbopack)
- `npm run build` / `npm start`: production build and server (`next start`)
- `npm test`: `node:test` (run through `tsx`) on `lib/orders.test.ts` (turning order input into shares and a total), `lib/server/account.test.ts` (the cash, equity and unrealized P&L math, bid/ask fills, buy-ins, splits and dividends), `lib/server/orderMatching.test.ts` (when orders fill, trigger or expire, and reserved cash), `lib/server/history.test.ts` (equity history and time-weighted return), `lib/server/technicals.test.ts` (returns, moving averages, RSI, returns less SPY's), `lib/server/earnings.test.ts` (which quarters and estimates the analysis sees), `lib/server/trackRecord.test.ts` (verdict outcomes and hit rates) and `lib/marketHours.test.ts` (the NYSE calendar)
- `npm run lint`: ESLint (`eslint-config-next`, flat config in `eslint.config.mjs`); `npm run typecheck`: `tsc --noEmit`
- TypeScript is pinned to 6.x because typescript-eslint doesn't support TypeScript 7 yet.

## Setup

`.env.local` (gitignored, loaded by Next.js) needs `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME`, `ALPHA_VANTAGE_API_KEY`, `OPENAI_API_KEY`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY`, and optionally `ALPHA_VANTAGE_REQUESTS_PER_MINUTE` (the plan's limit, default 150), `SIMULATED_SPREAD_BPS` (default 5), `ORDER_MATCH_INTERVAL_MS` (default 30000) and `BACKGROUND_JOBS=off`, and, for local testing only, `PRICE_OVERRIDES` and `MARKET_HOURS_OVERRIDE` (`open` or `closed`). The schema is in `db/schema.sql`: both tables have a `user_id` (the Clerk user ID, added by migration `005_user_id.sql`, which assigns existing rows to the user passed as `-v owner=user_...`), and every account query filters by it. A `transactions` table (`date` as `TIMESTAMPTZ`, `type` = `BUY`/`SELL`, `ticker`, `price`, `quantity`, `total`, and `reason`: NULL for the user's trades, `LIQUIDATION` for automatic buy-ins, added by migration `004_transactions_reason.sql`; `quote_time` and `fill_policy`, the quote a trade filled against and which side of it, `ASK`/`BID` quoted, `SIM_ASK`/`SIM_BID` simulated spread or `LAST`, NULL for older rows, and `price NUMERIC(18, 6)`/`total DECIMAL(14, 2)`, from migration `006_execution.sql`) and a `cash_activity` table, the cash ledger (added as `cash_transfers` by migration `003_cash_transfers.sql`, renamed by `007_cash_activity.sql`): `date` defaulting to `now()`, `type` = `DEPOSIT`/`WITHDRAW` (mock transfers) or `DIVIDEND_IN`/`DIVIDEND_OUT` (dividends received on longs, charged to shorts), `method` (a display label such as `Visa •••• 4242`, or the dividend's description), a positive `amount`, and for dividends `ticker` and `reference` (the ex-date; a partial unique index posts each at most once). An `orders` table (migration `008_orders.sql`) holds orders that don't fill right away: `side`, `order_type` (`MARKET` queued while the market is closed, `LIMIT`, `STOP`, `STOP_LIMIT`), `quantity` or (dollar-amount market orders only) `amount`, `limit_price`, `stop_price`, `time_in_force` (`DAY` with `expires_at`, the session close; `GTC`), `status` (`OPEN`, `FILLED`, `CANCELLED`, `EXPIRED`, `REJECTED`, with `status_reason`), `triggered_at` and `close_only` (a Portfolio close queued while the market is closed; migration `011_orders_close_only.sql`); a fill is a `transactions` row with `order_id`. A `watchlist` table (`user_id`, `ticker`, `added_at`; migration `009_watchlist.sql`) holds the tickers each user watches. A `verdict_log` table (migration `010_verdict_log.sql`, shared by all users) records each fresh ticker analysis: `ticker`, `verdict`, the newest close it saw (`price`, `price_date`), `generated_at`, `model` and `prompt_version` (`PROMPT_VERSION` in `lib/server/analysis.ts`; bump it when the prompts or inputs change, so the track record compares them). Migration 007 also adds `corporate_actions` (splits and dividends per ticker, shared by all users: `type` `SPLIT`/`DIVIDEND`, `ex_date`, `payment_date`, `factor`, `amount`) and `corporate_actions_checked` (when each ticker was last fetched). Read `DATE` columns as `::text`, since pg turns a `DATE` into a `Date` at the server's local midnight. `quantity` is `NUMERIC(18, 6)` for fractional shares, which `pg` returns as a string, so parse it before doing math. Schema changes for existing databases go in `db/migrations/` as numbered `.sql` files, applied by hand with `psql -U postgres -d ai_stocktrader -f <file>`.

## Architecture

**Server** (route handlers in `app/api/**/route.ts`, all paths under `/api` because the pages use `/trading/[ticker]`, `/portfolio` and `/transactions`; logic in `lib/server/`, each module marked `server-only`):
- `lib/server/errors.ts`: `HttpError`, `UpstreamError`, `errorResponse` (the error contract below) and `withUser`, which wraps every handler: it reads the Clerk session with `auth()` (made available by `clerkMiddleware()` in `proxy.ts`, Next 16's name for middleware), answers 401 without a signed-in user, passes the user ID to the handler (every account query and `withAccountLock` take it), and turns thrown errors into error responses. So every route, including `/api/rankings` and `/api/analysis/[ticker]`, needs a signed-in user. Requests are same-origin, so the Clerk session cookie authenticates them; there's no CORS.
- `lib/server/alphaVantage.ts`: Alpha Vantage calls (news, daily series, quotes and their caches, market status, splits and dividends, earnings: `fetchEarnings` (`EARNINGS`), `fetchEarningsEstimates` (`EARNINGS_ESTIMATES`) and `fetchNextReport` (`EARNINGS_CALENDAR`, a CSV endpoint, through `fetchAlphaVantageCsv`), each cached 12 hours per ticker). `lib/server/earnings.ts` is pure: `summarizeEarnings` picks the 4 latest reported quarters, the estimates for the quarter reported next and the 2 fiscal years from the one it ends in (with their 30- and 90-day revisions), and the next report date. `lib/server/corporateActions.ts`: `loadCorporateActions(tickers, refreshTickers)` returns the stored splits and dividends, first fetching any ticker never fetched (2 Alpha Vantage calls; a failure is logged and retried on a later request) and refreshing the open positions' tickers in the background once a day. `lib/server/analysis.ts`: OpenAI calls (ticker and position analyses, rankings). `lib/server/portfolio.ts`: database-backed account helpers (`getAccount`, `getPositions`, `withAccountLock`, `enforceCollateral`). `lib/server/db.ts` exports a `pg` Pool. `lib/server/account.ts` holds the pure account math (`computePositions`, `valueAccount`, `assessTrade`, `assessWithdrawal`, `planBuyIn`), so it can be tested without a database.
- In-process state (the caches, the Alpha Vantage request spacing, last known prices, the per-user lock queues and the pg Pool) is created once on `globalThis` (`singleton` in `lib/server/cache.ts`), because Next.js can load a module more than once (dev hot reloads, separate route bundles). It's still per process, so the app must run as one long-lived Node server (`next start` or `next dev`), not as serverless functions. Account safety doesn't depend on that: `withAccountLock` also takes a Postgres advisory lock.
- Market hours: `lib/marketHours.ts` (shared with the pages) has the NYSE regular session (9:30 to 16:00 Eastern), with the 2026-2028 holidays and 1:00 p.m. early closes hard-coded from NYSE's published calendar (extend the lists when NYSE publishes the next one; outside them only weekends are known). `lib/server/market.ts`'s `getMarketStatus`/`isMarketOpen` also treat the market as closed when Alpha Vantage's `MARKET_STATUS` (cached 1 minute) reports the U.S. closed during a scheduled session, falling back to the calendar if it can't be fetched. `MARKET_HOURS_OVERRIDE` forces it.
- Orders: `lib/server/orderMatching.ts` is pure (`evaluateOrder`: a queued market order fills at the ask/bid; a limit fills when marketable, a buy when the ask is at or below the limit, a sell when the bid is at or above it, at the quote; a stop triggers when the last price reaches it, then fills as a market order, or for a stop-limit becomes a limit order, `triggered_at` kept; DAY orders expire at `expires_at` even while closed; nothing fills while closed or without a current quote. `reservedForOrders`: each open order that would open or add to a position holds back its cost (a buy) or half its value (a short) at its limit, else stop, else current price). `lib/server/orders.ts` runs it on stored orders: `matchOrders(userId, label, db)` fills through `assessTrade` with the other orders' reservations unavailable (a fill that isn't allowed rejects the order), caps a `close_only` order at the position then open on its closing side (rejected when there's none), records a stop's trigger even when its fill has to wait, treats a stale quote (`isStaleQuote`) as none, and judges each order at the time and market status after its quotes arrive, rechecked right before the fill, and `reservedCashFor`. `lib/server/upkeep.ts`'s `updateAccount` (dividends, buy-in check, then `matchOrders`) runs from `GET /api/account` and `GET /api/portfolio`, and from the background job: `instrumentation.ts` starts `lib/server/jobs.ts` in the Node runtime, which every 30s runs `updateAccount` for each user with open orders or a short (a negative raw share count, or any trade in a ticker that has split, since raw counts mix pre- and post-split shares) (the process holding a Postgres advisory lock is the only one that does), warming the quote cache with every ticker first. It reads `process.env` when it starts, so restart the dev server after changing the overrides. Orders are judged on prices sampled that often, so a briefer cross can be missed.
- Shapes shared with the pages (rows, `Account`, verdicts, request bodies) are in `lib/types.ts`.

Routes. Market data (prices, rankings, analyses) and its caches are shared by all users:
- `GET /api/analysis/[ticker]`: `analyzeTicker` fetches the ticker's latest news (dots become hyphens, since the news endpoint expects `BRK-A` where prices use `BRK.A`; articles below `MIN_NEWS_RELEVANCE` to the ticker are dropped) plus technicals computed from its full daily closes (`computeTechnicals` in `lib/server/technicals.ts`: 5-session, 1-month and 3-month returns, the 1- and 3-month returns less SPY's (from SPY's compact series, shared with the performance chart), distance from the 50- and 200-day averages, 14-day RSI), its earnings and estimates (`summarizeEarnings`), and its company overview (valuation, analyst target price and rating counts), each left out when Alpha Vantage has none. The system prompt and `ANALYSIS_RULES` frame the task as the likely price effect over the horizon: whether the news is new or already reflected in the recent returns, results against expectations over tone, and an earnings report within the horizon as a catalyst and a risk. It returns `{ verdict, analysis, horizon, evidence, counterarguments, risks, catalysts, sources, generatedAt, dataAsOf, model }`: `BUY` (the evidence points to the price rising over the fixed 1-to-4-week horizon), `SELL` (falling; selling includes shorting) or `HOLD` (only when balanced or too thin); `analysis` is the thesis, one paragraph that must agree with the verdict; each list has 2 to 4 items; the model cites articles by number, and the server keeps only real ones as `sources` (title, link, time) and strips inline numbers from the text. No confidence percentages or price targets (JSON mode, temperature 0). Article numbers left in the text, in brackets or parentheses, are stripped. Cached per ticker for 30 minutes with its inputs (`publicAnalysis` leaves them out of the response). Each fresh verdict is inserted into `verdict_log` in the background (a failure is only logged). `peekTickerVerdict` reads a finished cached verdict without fetching.
- `GET /api/rankings`: `{ buy: [...], sell: [...] }`, up to 5 tickers each (`buildRankings`, cached 30 minutes). It fetches the latest 1000 market news articles, groups them by the companies each is mainly about (`mainTickers`: the most relevant tickers, so a bank's analyst note on another company isn't counted for the bank; crypto, forex, preferred, warrant, unit and rights symbols are skipped), and scores each stock from Alpha Vantage's per-ticker sentiment (sum / √articles). The 30 most bullish and 30 most bearish stocks (average sentiment at least ±0.15) go to one OpenAI call with their newest 4 articles each, and it shortlists up to 15 per side. Picking by coverage alone left the sell side nearly empty, since the most-covered stocks are mostly neutral or bullish. `confirmRankings` then runs `analyzeTicker` on the candidates in order and keeps only those whose verdict matches the side (`BUY` or `SELL`), so a side can have fewer than 5. Each refresh logs the funnel (articles, stocks, each candidate's verdict) to the server console. The listed tickers' cached analyses are kept at least as long as the rankings, so the Trading page shows the same verdict that put the stock in the ranking.
- `GET /api/analysis/track-record`: how logged verdicts turned out, per prompt version (newest first): for 5 and 20 sessions after each verdict's `price_date` close, per verdict the count, average price return, average return less SPY's between the same closes, and a hit rate (BUY: beat SPY; SELL: trailed it; HOLD: none). One verdict per prompt version, ticker and session (the last), only those at least 7 days old; splits already in `corporate_actions` are undone, but none are fetched, so a split on a ticker never traded isn't. Scored by `scoreVerdicts` (`lib/server/trackRecord.ts`, pure) and cached 12 hours.
- `GET /api/quote/[ticker]`: the ticker's `Quote` (`fetchQuote`): price, previous close, bid/ask, quote time and delay (`realtime`, or `end-of-day` once the price has reached the session close). `GET /api/market`: `getMarketStatus()` (`{ open, session, nextOpen, nextClose, earlyClose, calendarKnown }`).
- `GET /api/quote/[ticker]/overview`: `fetchCompanyOverview` (Alpha Vantage `OVERVIEW`, cached 24 hours): name, exchange, sector, industry, market cap, P/E, forward P/E, dividend yield, beta, 52-week range and dividend dates, `null` where it has none; funds and unknown tickers get 404. `GET /api/trading/[ticker]/intraday?days=1..20`: the last sessions of regular-hours 5-minute bars (`fetchIntraday`, `TIME_SERIES_INTRADAY` with the entitlement, a month at a time, cached 60s). `GET /api/search?q=`: up to 8 matches from `SYMBOL_SEARCH` (`searchSymbols`, U.S. listings first, cached 24 hours per query).
- `GET /api/watchlist`: the user's watched tickers, newest first, with price and previous close (`fetchQuotes`) and the AI verdict only if one is already cached (`peekTickerVerdict`, so watching never triggers an analysis). `POST /api/watchlist` (`{ ticker }`), `GET /api/watchlist/[ticker]` (`{ watched }`, no prices) and `DELETE /api/watchlist/[ticker]`.
- `GET /api/trading/[ticker]`: Alpha Vantage `TIME_SERIES_DAILY` (full history), passed through as is. Every price request sends `entitlement=realtime`, because even premium keys get only end-of-day data without it; there's no delayed fallback. The newest bar is today's partial day, and its close is the price shown and traded. A key without the realtime entitlement gets a `Note` back, which fails the request (502). Alpha Vantage replies with an empty `{}` both for unknown symbols and during its own price-data outages, and the two can't be told apart.
- `POST /api/trading/[ticker]`: body `{ order: { type, quantity | amount }, close? }`, a market order for a number of shares or a dollar amount. While the market is open the server fills it from its own quote, never from the request (the market status is read inside the account lock, after the quote): buys at the ask, sells at the bid (`fillPrice`), turns an amount into shares with `toOrder`, stamps `now()`, records `quote_time`/`fill_policy`, and returns `{ fill }`. While it's closed, the order is checked at the current price and queued as a DAY `MARKET` order for the open, returning `{ order }`. Trades that only reduce a position (covers, sales of longs) are always allowed and are paid from total cash, restricted included. Anything that opens or adds to a position, including the new side of a flip, goes through `assessTrade`: replayed with the trade added, it must leave no collateral shortfall. So a buy needs its cost in available cash (which excludes what open orders reserve) and a new short needs 50% of its value; during a margin call neither is allowed (400). A short without a current price blocks these with 502. `close: true` (the Portfolio page) returns 409 instead of flipping when the trade is larger than the open position or the position is gone, such as after a buy-in; a closing dollar amount that covers the whole position closes it exactly. A close queued while the market is closed is stored `close_only`, so it can't flip the position when it fills. The buy-in check runs after the insert.
- `POST /api/orders`: body `{ order: { ticker, side, orderType: LIMIT | STOP | STOP_LIMIT, quantity, limitPrice?, stopPrice?, timeInForce: DAY | GTC } }`, accepted at any time. A stop must be on the right side of the current price (400 otherwise). An order that opens or adds to a position is checked with `assessTrade` as if it filled at its limit (or stop), with the other open orders' reservations unavailable. While the market is open it's matched right away, so a marketable order fills at once. Returns `{ order }`. `GET /api/orders?status=open|all&ticker=`: newest first (`open` matches them first). `DELETE /api/orders/[id]`: cancels an open order (404 not the user's, 409 no longer open).
- `GET /api/portfolio/history?range=1W|1M|3M|YTD|1Y|ALL`: daily equity rebuilt from the trades, cash ledger, splits and each traded ticker's daily closes (`fetchDailyCloses`, `compact` or `full` depending on how far back the first activity is, cached 12 hours), by `equityHistory` (`lib/server/history.ts`), with the time-weighted return (each day's return with the deposits and withdrawals since the previous trading day taken out, weekends and holidays included, chained; dividends count as return; each day is valued with that day's splits, not the next day's (`computePositions`' `splitsThrough`)) and SPY's price return, both measured from the range's first day. A return is only meaningful with positive equity, so a day that starts or ends at zero or below adds nothing and is a gap on the chart (`twr: null`). The range totals are `twr` and `benchmarkReturn`. There's no 1D range.
- `GET /api/transactions`: all rows, newest first, each with `realized_pnl` (`id` breaks ties for rows migrated from the old `DATE` column, which all sit at midnight)
- `GET /api/portfolio`: open positions `[{ ticker, quantity, avgCost, price, bid, ask, error }]`, computed from `transactions` by `computePositions` (no positions table), with the traded tickers' splits applied in date order (before the first trade on or after a split's date: shares × factor, average cost ÷ factor, so cost basis and cash don't change). Every replay of stored trades (`getAccount`, `getPositions`) goes through the splits; `assessTrade` takes them too. The replay also books realized P&L on the part of each trade that reduces or closes a position, against its average cost (`realizedPnl`, and per transaction). Rows include `previousClose`, for the Today column. `quantity` is signed: Trading-page sells past zero are intentional shorts, so a negative position is a short. Cost basis is average cost: adding to a position re-averages it, reducing it keeps the average, and a trade that flips the side opens the remainder at the trade price. Quantities are rounded to 6 decimals after each trade (`roundShares`), so float drift can't leave a tiny position open. Rows also carry `bid`/`ask`. Prices come from `fetchQuotes` (`lib/server/alphaVantage.ts`), with `Promise.allSettled`, so a ticker whose price fails gets `price: null` and an `error` instead of failing the whole response. `fetchQuotes` fetches every uncached ticker together with the premium bulk endpoints (`REALTIME_BULK_QUOTES` plus `REALTIME_BULK_BID_ASK_PRICES`, 100 symbols per call); a plan without them gets artificial sample data with a "premium endpoint" `message`, which `fetchAlphaVantage` turns into a `NotEntitledError`, and the endpoint is then skipped for an hour in favor of each ticker's compact `TIME_SERIES_DAILY` (same entitlement and newest-bar close as `/api/trading/[ticker]`, previous bar for the previous close). The current key's plan includes them. Without quoted bid/ask, a simulated spread of `SIMULATED_SPREAD_BPS` basis points (at least a cent, at most half the price so the bid stays positive; 0 turns it off and fills at the last price) is centered on the last price. Each ticker's quote is cached for 15s (failures aren't kept), so `/api/portfolio`, `/api/account` and trades share one call. The last price is remembered in memory, which `fetchPrices` falls back to (listing the ticker in `staleTickers`) when a fetch fails. `PRICE_OVERRIDES` (env JSON such as `{"TSTA": 120}`) fixes prices without Alpha Vantage, with no spread, for local testing only.
- `GET /api/account`: `{ totalCash, availableCash, restrictedCash, reservedCash, realizedPnl, netDividends, collateralRequirement, collateralShortfall, collateralRatio, shortLiability, marginStatus, equity, unrealizedPnl, missingPrices, positions: [{ ticker, quantity }], liquidations }` for the header (`liquidations`: the past week's buy-in trades). The cash model (`valueAccount`):
  - Total cash is a plain ledger: net cash activity (deposits and dividends received, less withdrawals and dividends charged to shorts) plus every sell's total minus every buy's, so a short sale's proceeds land in it and a cover pays from it. It starts from all past trades.
  - Dividends (`postDividends`, from `updateAccount`): `planDividends` finds each stored dividend whose payment date has come, on a ticker held at its ex-date's open (`positionsAt`: trades before that day, splits through it), not yet posted, and it's inserted into `cash_activity` dated at the payment date's close. Longs receive shares × amount, shorts pay it.
  - Short collateral: 150% of the shorts' current market value (`SHORT_COLLATERAL_RATE`) is restricted cash; the rest of total cash, less the cash reserved for open orders, is available cash, never negative. When total cash can't meet the requirement, the gap is `collateralShortfall` (the deposit that would make the account compliant, including any negative cash). `marginStatus` is `ok`, `margin_call` (shortfall), or `buy_in` (total cash below 130% of short liability, `BUY_IN_RATE`).
  - `equity = total cash + Σ long market value - Σ short market liability` (also net deposits + realized + unrealized P&L + net dividends; the tests check it), and `unrealizedPnl = Σ long (market value - cost basis) + Σ short (sale proceeds - market liability)`, with cost basis and proceeds at `avgCost × shares`. Collateral only splits total cash, so it changes neither. Trades at the market price never change equity; the tests check this.
  - A position without a current price is valued at its last known price, or at its cost, and listed in `missingPrices`. Stale prices never approve a risky action or trigger a buy-in. During a scheduled session (the NYSE calendar), a quote that's end-of-day or more than 15 minutes old (`isStaleQuote`) counts as stale too: `fetchPrices` lists it in `staleTickers` (it's still shown), and a market order on it fails with 502. `insertTrade` refuses a fill without a positive price and quantity.
  - Automatic buy-in (`planBuyIn`, run by `enforceCollateral`): below 130%, every short is covered by the same fraction, just enough to restore 150% (it takes $2 of covers per $1 of shortfall, a little more at the ask), and longs are sold pro rata only if covering every short leaves negative cash. Covers fill at the ask and sales at the bid. Prices only arrive with requests, so it runs lazily, from `GET /api/account`, `GET /api/portfolio` (both through `updateAccount`, which posts dividends first) and after each trade, and only while the market is open; those GETs can write. Each user's account changes run one at a time through `withAccountLock(userId, fn)`: an in-process queue per user in front of a Postgres advisory lock (`pg_advisory_lock(hashtext(user_id))`) on a dedicated pool client, which `fn` gets and must use for its queries (`getAccount`, `insertTrade`, `inTransaction`). The client is held for the whole call, Alpha Vantage requests included, so the pool allows 20 connections.
- `POST /api/transfers`: body `{ transfer: { type, method, amount } }`, inserts a `DEPOSIT` or `WITHDRAW` into `cash_activity` (the server sets the date). 400 for a bad type, an empty method, an amount outside $0.01 to $99,999,999.99, or a withdrawal above the available cash (`assessWithdrawal`; withdrawals never come from short collateral or cash reserved for orders, and are blocked during a margin call). Deposits skip the lock and the buy-in check, so a deposit meant to meet a margin call counts first.
- `GET /api/transfers`: all cash activity (deposits, withdrawals, dividends), newest first
- `GET /api/portfolio/[ticker]/analysis`: the same shape for an open position (404 if there's none). `analyzePosition` derives the verdict from the ticker's `analyzeTicker` verdict, so it can't contradict the Trading page: a long is `SELL` on `SELL` and `HOLD` otherwise, a short is `COVER` on `BUY` and `HOLD` otherwise. A second OpenAI call (temperature 0) then writes the structured analysis for the position explaining that verdict, from the same inputs `analyzeTicker` used (cached with it, so no extra Alpha Vantage call) plus the position: shares, average cost, unrealized P&L and weight in the account's equity (the route values the account with the cached quotes). Cached 30 minutes per user, ticker, side and verdict.

All AI prompts live on the server (`lib/server/analysis.ts`). There's deliberately no generic prompt endpoint, so the OpenAI key can't be used as an open proxy. Shared helpers: `cachePromise` (`lib/server/cache.ts`; caches a promise per key, shared by concurrent callers; failures aren't kept), `fetchAlphaVantage` (starts requests at least 300ms apart and at most `ALPHA_VANTAGE_REQUESTS_PER_MINUTE` in any 61 seconds across all routes, queuing the rest, because Alpha Vantage rejects more than 5 a second with a "Burst pattern detected" `Information` reply and more than the plan's per-minute limit, which can still trip during a long run of calls, so it's retried up to twice after a pause), `fetchNews` (`NEWS_SENTIMENT` sorted latest first, as `{ title, summary, published, tickers: [{ ticker, relevance }] }`) and `fetchTickerNews` (hyphenated symbol, 404 when no relevant article), `askAnalyst` (system prompt plus OpenAI call) and `analyzeNews` (articles with their publication times, then the prompt), and `errorResponse`.

Error contract: `withUser` catches every handler's errors and calls `errorResponse`, which logs `METHOD path: message` and always returns `{ error: message }` with one of these statuses:
- 401: no signed-in user (`withUser`: no session, or an invalid or expired one).
- 502: a bad reply from Alpha Vantage, OpenAI, or the model. Alpha Vantage reports rate limits, missing entitlements and bad symbols with HTTP 200 and a `Note`/`Information`/`Error Message` body (or `{}`), so `fetchAlphaVantage` throws an `UpstreamError` whenever the expected key is missing. OpenAI SDK errors also map to 502.
- 400: a rejected request, such as a buy, short or withdrawal without enough available cash, or one during a margin call (`HttpError` with status 400; `UpstreamError` extends `HttpError`).
- 409: a Portfolio close (`close: true`) larger than the open position.
- 404: `/api/analysis/[ticker]` and `/api/portfolio/[ticker]/analysis` when the ticker has no news, or the latter when there's no open position (`UpstreamError` with an explicit status).
- 504: an upstream call timed out. Alpha Vantage times out at 30s (its response times vary widely), OpenAI at 30s with 1 retry, and the Postgres connection at 5s (in `lib/server/db.ts`).
- 500: anything else, such as database errors.

**Client** (React 19, App Router pages in `app/`: `/` (`app/page.tsx`), `/trading/[ticker]`, `/transactions`, `/portfolio`, `/deposit`, `/withdraw`; components in `components/`, all client components (`"use client"`) except a few presentational ones; each page renders `Header` and its main component):
- Auth (`@clerk/nextjs`): `app/layout.tsx` wraps the app in `ClerkProvider` (it reads `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`), and `components/AppShell.tsx` renders the pages inside `<Show when="signed-in">` with `SignInPage` (Clerk's `<SignIn>`, which links to sign-up) as the fallback, so no page loads while signed out. The header ends with Clerk's `<UserButton>` (profile, sign-out).
- API calls use axios with relative `/api/...` paths (`/api/rankings`, `/api/trading/${ticker}`, …), same origin, so Clerk's session cookie goes with them. Use axios rather than `fetch` so non-2xx responses throw.
- Navigation uses `next/link` (`href`) and `useRouter` from `next/navigation`. The logo is a static import of `public/AIStockTraderLogo.png` rendered with `next/image`. `CandlestickChart` loads `react-plotly.js` with `next/dynamic` and `ssr: false`, since Plotly needs `window` (Plotly 3 only takes `title: { text }`, not a string).
- Each fetching component keeps an `error` state and shows `apiErrorMessage(error)` (`lib/apiError.ts`: the response's `error`, or the request's own message) in place of its loading text.
- Home → `Watchlist` (`/api/watchlist`: price, today's change, cached verdict, remove) above `Rankings`, which calls `/api/rankings` and renders two presentational `StockRanking` tables. `TickerSearchBar` (in the header) suggests tickers from `/api/search` from the first character, 250ms after typing stops, with arrow keys and Enter to pick one. Trading → `TradingInterface` has a `WatchlistStar` next to the ticker, and loads the time series (`QuoteDetails`: day range, volume and 52-week range from it, plus the company overview; `CandlestickChart`, with 1D and 5D ranges from the intraday route and 1M to Max filtered from the daily series; and the price if the quote fails) and, separately, `/api/quote/[ticker]` and `/api/market` (`Price` with bid/ask and the quote's time and delay, `MarketStatusBadge`, `BuySellFunctionality`, which needs the quote and reloads it after a trade); `AIAnalysis` loads `/api/analysis/[ticker]` independently and renders it with `AnalysisDetailsView`: verdict and horizon, the thesis, collapsible Evidence, Counterarguments, Risks, Catalysts and Sources (linked), and when and by which model it was made. `BuySellFunctionality` has an order-type select (Market, Limit, Stop, Stop limit), stop and limit price inputs and a Day/Until cancelled select for conditional orders (which are for shares; the $ mode is market-only). Market orders post `{ order }` only (no price) to `/api/trading/[ticker]`, previewed at the ask and bid, showing the fill or, while the market is closed ("Queue buy"), the queued order; conditional orders post to `/api/orders`. `OpenOrders` lists open orders with a Cancel button (on Trading for that ticker, under the Portfolio table for all), and is reloaded after each order.
- Portfolio → `PortfolioList` loads `/api/portfolio` and renders a `PortfolioRow` per position. Each row closes the position (SELL at the bid for longs, BUY at the ask to cover shorts) through `POST /api/trading/[ticker]` with `close: true`, then updates its quantity locally from the filled row instead of refetching every price. While the market is closed the closing order is queued for the open ("Queue sell"). `PortfolioList` also loads `/api/market` to show `MarketStatusBadge` and label the buttons. Above the table, `PerformanceChart` (react-plotly via `next/dynamic`) shows equity, the range's gain excluding deposits and withdrawals, the time-weighted return and SPY's, with range buttons; under the unrealized P/L total are today's change, realized P/L and net dividends. Each row has a Today column (price minus previous close, times the signed quantity). The round AI button calls `/api/portfolio/[ticker]/analysis` only on first open, caches the result, and shows it (verdict Hold, Sell or Cover) with `AnalysisDetailsView`. `QuantityStepper` is shared with `BuySellFunctionality`.
- Account: `AccountProvider` (`context/AccountContext.tsx`, inside `AppShell`, keyed by user ID so a new user gets a fresh one) loads `/api/account` once per signed-in user and exposes `{ account, error, refreshAccount }` through `useAccount()`, so the figures survive navigation. The header has three regions: logo and search, `AccountSummary` (Available, Equity, Unrealized P&L), and the page links plus Deposit/Withdraw pills. `BuySellFunctionality`, `PortfolioRow` and `TransferForm` call `refreshAccount()` after a successful POST. `AccountSummary` shows restricted cash and cash reserved for orders under Available, and `MarginBanner` (under the header) shows a margin call and any buy-ins from the past week (dismissal remembered in `localStorage` per user). `BuySellFunctionality` disables Buy (unless the ticker is short) when the total exceeds Available, and Sell (unless the ticker is long) when half the total does; both during a margin call. The server stays authoritative for flips.
- Deposit/Withdraw pages render `TransferForm` with `direction="deposit" | "withdraw"`: method tiles, per-method fields with format checks (Luhn, expiry, CVC, ABA routing checksum, email; helpers in `lib/payments.ts`), and a `$` `QuantityStepper` (withdrawals capped at Available). Only `describeMethod`'s label and the amount are sent. Transactions (`TransactionsList`) has tabs, kept in the URL as `?tab=` (the page passes it as a prop): Orders (`/api/orders?status=all`, with each status and reason), Trades (`/api/transactions`, with each fill's side, quote time and order, and realized P/L) and Cash Activity (`/api/transfers`).
- Fractional orders: both trade forms have a `TradeModeToggle` (Shares | $) and an editable decimal `QuantityStepper` (6 decimals for shares, 2 for dollars). `toOrder` in `lib/orders.ts` turns the input into `{ quantity, total }`: a dollar amount becomes `amount / price` shares rounded down to whole millionths, the total is always those shares at the price (so rounding can't buy more than was paid), an order worth less than a cent is empty (400), and on the portfolio an amount that covers the whole position closes it exactly.
- Props are typed with TypeScript (no prop-types or `defaultProps`); put defaults in the destructured parameters. Parameter defaults don't apply to `null`.

**Styling:** Bootstrap 4.6 (the npm package's CSS, no Bootstrap JS) is imported first in `app/layout.tsx`, then `app/globals.css` (Tailwind's directives and base styles) and `app/App.css` (custom classes). Tailwind is v3 (`tailwind.config.ts`, `postcss.config.js`), with preflight disabled so Bootstrap keeps its base styles; v4's cascade layers would lose to Bootstrap's unlayered CSS. Class names shared by both libraries (`mt-5`, `py-4`, `mr-2`, `shadow-lg`) resolve to Tailwind's values, because Tailwind's CSS comes after Bootstrap's.

## Repo notes

- Each rankings refresh (the first home page load in 30 minutes) costs 1 Alpha Vantage call plus 1 OpenAI call, plus 1 of each per candidate checked (usually 14 to 20, up to 30, fewer when their analyses are already cached), and takes tens of seconds. Each trading page load costs 2 Alpha Vantage calls, the full series and the quote (3 when its analysis isn't cached; the quote is shared with the 15s cache), plus the company overview once a day per ticker and 1 intraday call per 60s when the 1D or 5D chart is opened; each new search query costs 1 call (cached a day); the watchlist costs 1 call per ticker per 15s (1 in all with the bulk endpoints) plus 1 OpenAI call when it isn't cached, each portfolio page load costs 1 Alpha Vantage call per open position (plus, for the performance chart, 1 per ticker ever traded and 1 for SPY every 12 hours), each full app load (the header's `/api/account`) costs 1 Alpha Vantage call per open position (plus 2 per traded ticker the first time it's seen, and 2 per open position once a day, for splits and dividends), each trade or withdrawal that adds risk costs 1 call per open short (for the collateral check), and the background job costs 1 call per ticker with open orders or shorts per run, every 30s, while the market is open (shared with the 15s quote cache; 1 call in all with the bulk endpoints), each portfolio AI button costs 1 OpenAI call (plus the ticker's analysis when it isn't cached) the first time it's opened in 30 minutes. A ticker analysis costs 1 OpenAI call and 1 Alpha Vantage call for its news, plus its full daily series (cached 12 hours), SPY's compact series (12 hours, shared by all tickers), its earnings, estimates and next report date (3 calls, cached 12 hours) and company overview (cached 24 hours) when they aren't cached, so a rankings refresh's candidate checks cost up to 6 Alpha Vantage calls each. The track record costs 1 call per ticker in the verdict log plus SPY when it isn't cached (12 hours), so the first load after a restart can take a while. Latest quotes are cached for 15s (shared by `/api/account`, `/api/portfolio`, `/api/quote` and trades), the market status for 1 minute (only checked during scheduled sessions), and with the bulk endpoints a whole portfolio costs 1 call (2 with bid/ask) instead of 1 per position, and rankings, ticker analyses and position analyses for 30 minutes; nothing else is, so this counts against the Alpha Vantage plan's rate limit (the current plan allows 150 requests a minute; a rankings refresh can use most of a minute's worth, and later calls wait their turn).
