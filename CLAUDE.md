# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

AI StockTrader is a mock-trading web app: a single Next.js 16 (App Router) app in TypeScript, with pages and API route handlers in one project, backed by PostgreSQL, with sign-in through Clerk; each user has their own account. Stock prices and news come from Alpha Vantage; buy/sell rankings and per-ticker analysis come from OpenAI (`gpt-6-luna`, reasoning off) sentiment analysis of news titles/summaries, and a ticker only appears in a ranking when its own analysis agrees.

## Commands

From the repo root:

- `npm install`: install dependencies
- `npm run dev`: dev server on http://localhost:3000 (pages and `/api/*`; Turbopack)
- `npm run build` / `npm start`: production build and server (`next start`)
- `npm test`: `node:test` (run through `tsx`) on `lib/server/account.test.ts`, which covers the cash, equity and unrealized P&L math
- `npm run lint`: ESLint (`eslint-config-next`, flat config in `eslint.config.mjs`); `npm run typecheck`: `tsc --noEmit`
- TypeScript is pinned to 6.x because typescript-eslint doesn't support TypeScript 7 yet.

## Setup

`.env.local` (gitignored, loaded by Next.js) needs `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME`, `ALPHA_VANTAGE_API_KEY`, `OPENAI_API_KEY`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY`, and optionally `ALPHA_VANTAGE_ENTITLEMENT` and `PRICE_OVERRIDES`. The schema is in `db/schema.sql`: both tables have a `user_id` (the Clerk user ID, added by migration `005_user_id.sql`, which assigns existing rows to the user passed as `-v owner=user_...`), and every account query filters by it. A `transactions` table (`date` as `TIMESTAMPTZ`, `type` = `BUY`/`SELL`, `ticker`, `price`, `quantity`, `total`, and `reason`: NULL for the user's trades, `LIQUIDATION` for automatic buy-ins, added by migration `004_transactions_reason.sql`) and a `cash_transfers` table for mock deposits and withdrawals (`date` defaulting to `now()`, `type` = `DEPOSIT`/`WITHDRAW`, `method`, a display label such as `Visa •••• 4242`, and `amount`; added by migration `003_cash_transfers.sql`). `quantity` is `NUMERIC(18, 6)` for fractional shares, which `pg` returns as a string, so parse it before doing math. Schema changes for existing databases go in `db/migrations/` as numbered `.sql` files, applied by hand with `psql -U postgres -d ai_stocktrader -f <file>`.

## Architecture

**Server** (route handlers in `app/api/**/route.ts`, all paths under `/api` because the pages use `/trading/[ticker]`, `/portfolio` and `/transactions`; logic in `lib/server/`, each module marked `server-only`):
- `lib/server/errors.ts`: `HttpError`, `UpstreamError`, `errorResponse` (the error contract below) and `withUser`, which wraps every handler: it reads the Clerk session with `auth()` (made available by `clerkMiddleware()` in `proxy.ts`, Next 16's name for middleware), answers 401 without a signed-in user, passes the user ID to the handler (every account query and `withAccountLock` take it), and turns thrown errors into error responses. So every route, including `/api/rankings` and `/api/analysis/[ticker]`, needs a signed-in user. Requests are same-origin, so the Clerk session cookie authenticates them; there's no CORS.
- `lib/server/alphaVantage.ts`: Alpha Vantage calls (news, daily series, latest prices and their caches). `lib/server/analysis.ts`: OpenAI calls (ticker and position analyses, rankings). `lib/server/portfolio.ts`: database-backed account helpers (`getAccount`, `getPositions`, `withAccountLock`, `enforceCollateral`). `lib/server/db.ts` exports a `pg` Pool. `lib/server/account.ts` holds the pure account math (`computePositions`, `valueAccount`, `assessTrade`, `assessWithdrawal`, `planBuyIn`), so it can be tested without a database.
- In-process state (the caches, the Alpha Vantage request spacing, last known prices, the per-user account locks and the pg Pool) is created once on `globalThis` (`singleton` in `lib/server/cache.ts`), because Next.js can load a module more than once (dev hot reloads, separate route bundles). It's still per process, so the app must run as one long-lived Node server (`next start` or `next dev`), not as serverless functions.
- Shapes shared with the pages (rows, `Account`, verdicts, request bodies) are in `lib/types.ts`.

Routes. Market data (prices, rankings, analyses) and its caches are shared by all users:
- `GET /api/analysis/[ticker]`: `analyzeTicker` fetches the ticker's latest news (dots become hyphens, since the news endpoint expects `BRK-A` where prices use `BRK.A`; articles below `MIN_NEWS_RELEVANCE` to the ticker are dropped) and returns `{ verdict, analysis }`: `BUY` (news points to the price rising), `SELL` (falling; selling includes shorting) or `HOLD` (only when balanced or too thin), and a one-paragraph explanation that must agree with it (JSON mode, temperature 0). Cached per ticker for 30 minutes.
- `GET /api/rankings`: `{ buy: [...], sell: [...] }`, up to 5 tickers each (`buildRankings`, cached 30 minutes). It fetches the latest 1000 market news articles, groups them by the companies each is mainly about (`mainTickers`: the most relevant tickers, so a bank's analyst note on another company isn't counted for the bank; crypto, forex, preferred, warrant, unit and rights symbols are skipped), and scores each stock from Alpha Vantage's per-ticker sentiment (sum / √articles). The 30 most bullish and 30 most bearish stocks (average sentiment at least ±0.15) go to one OpenAI call with their newest 4 articles each, and it shortlists up to 15 per side. Picking by coverage alone left the sell side nearly empty, since the most-covered stocks are mostly neutral or bullish. `confirmRankings` then runs `analyzeTicker` on the candidates in order and keeps only those whose verdict matches the side (`BUY` or `SELL`), so a side can have fewer than 5. Each refresh logs the funnel (articles, stocks, each candidate's verdict) to the server console. The listed tickers' cached analyses are kept at least as long as the rankings, so the Trading page shows the same verdict that put the stock in the ranking.
- `GET /api/trading/[ticker]`: Alpha Vantage `TIME_SERIES_DAILY` (full history), passed through as is. It sends `entitlement=ALPHA_VANTAGE_ENTITLEMENT` (default `delayed`), because even premium keys get only end-of-day data without it. With the entitlement, the newest bar is today's partial day, and its close is the price shown and traded. A key without that entitlement gets a `Note` back. Alpha Vantage replies with an empty `{}` both for unknown symbols and during its own price-data outages, and the two can't be told apart.
- `POST /api/trading/[ticker]`: body `{ transaction: {...}, close? }`, inserts into `transactions`. Trades that only reduce a position (covers, sales of longs) are always allowed and are paid from total cash, restricted included. Anything that opens or adds to a position, including the new side of a flip, goes through `assessTrade`: replayed with the trade added, it must leave no collateral shortfall. So a buy needs its cost in available cash and a new short needs 50% of its value; during a margin call neither is allowed (400). A short without a current price blocks these with 502. `close: true` (the Portfolio page) returns 409 instead of flipping when the trade is larger than the open position, such as after a buy-in. The buy-in check runs after the insert.
- `GET /api/transactions`: all rows, newest first (`id` breaks ties for rows migrated from the old `DATE` column, which all sit at midnight)
- `GET /api/portfolio`: open positions `[{ ticker, quantity, avgCost, price, error }]`, computed from `transactions` by `computePositions` (no positions table). `quantity` is signed: Trading-page sells past zero are intentional shorts, so a negative position is a short. Cost basis is average cost: adding to a position re-averages it, reducing it keeps the average, and a trade that flips the side opens the remainder at the trade price. Quantities are rounded to 6 decimals after each trade (`roundShares`), so float drift can't leave a tiny position open. Prices come from `TIME_SERIES_DAILY` (`compact`, same entitlement and newest-bar close as `/api/trading/[ticker]`), fetched in parallel with `Promise.allSettled`, so a ticker whose price fails gets `price: null` and an `error` instead of failing the whole response. `fetchLatestPrice` caches each ticker's price promise for 60s (failures aren't kept), so `/api/portfolio` and `/api/account` share one Alpha Vantage call per ticker. It also remembers each ticker's last price in memory, which `fetchPrices` falls back to (listing the ticker in `staleTickers`) when a fetch fails. `PRICE_OVERRIDES` (env JSON such as `{"TSTA": 120}`) fixes prices without Alpha Vantage, for local testing only.
- `GET /api/account`: `{ totalCash, availableCash, restrictedCash, collateralRequirement, collateralShortfall, collateralRatio, shortLiability, marginStatus, equity, unrealizedPnl, missingPrices, positions: [{ ticker, quantity }], liquidations }` for the header (`liquidations`: the past week's buy-in trades). The cash model (`valueAccount`):
  - Total cash is a plain ledger: net transfers plus every sell's total minus every buy's, so a short sale's proceeds land in it and a cover pays from it. It starts from all past trades.
  - Short collateral: 150% of the shorts' current market value (`SHORT_COLLATERAL_RATE`) is restricted cash; the rest of total cash is available cash, never negative. When total cash can't meet the requirement, the gap is `collateralShortfall` (the deposit that would make the account compliant, including any negative cash). `marginStatus` is `ok`, `margin_call` (shortfall), or `buy_in` (total cash below 130% of short liability, `BUY_IN_RATE`).
  - `equity = total cash + Σ long market value - Σ short market liability`, and `unrealizedPnl = Σ long (market value - cost basis) + Σ short (sale proceeds - market liability)`, with cost basis and proceeds at `avgCost × shares`. Collateral only splits total cash, so it changes neither. Trades at the market price never change equity; the tests check this.
  - A position without a current price is valued at its last known price, or at its cost, and listed in `missingPrices`. Stale prices never approve a risky action or trigger a buy-in.
  - Automatic buy-in (`planBuyIn`, run by `enforceCollateral`): below 130%, every short is covered by the same fraction, just enough to restore 150% (it takes $2 of covers per $1 of shortfall), and longs are sold pro rata only if covering every short leaves negative cash. Prices only arrive with requests, so it runs lazily, from `GET /api/account`, `GET /api/portfolio` and after each trade; those GETs can write. Each user's account changes run one at a time through `withAccountLock(userId, fn)`, an in-process queue per user (it assumes one server process).
- `POST /api/transfers`: body `{ transfer: { type, method, amount } }`, inserts into `cash_transfers` (the server sets the date). 400 for a bad type, an empty method, an amount outside $0.01 to $99,999,999.99, or a withdrawal above the available cash (`assessWithdrawal`; withdrawals never come from short collateral and are blocked during a margin call). Deposits skip the lock and the buy-in check, so a deposit meant to meet a margin call counts first.
- `GET /api/transfers`: all deposits and withdrawals, newest first
- `GET /api/portfolio/[ticker]/analysis`: `{ verdict, analysis }` for an open position (404 if there's none). `analyzePosition` derives the verdict from the ticker's `analyzeTicker` verdict, so it can't contradict the Trading page: a long is `SELL` on `SELL` and `HOLD` otherwise, a short is `COVER` on `BUY` and `HOLD` otherwise. A second OpenAI call (temperature 0) then writes a paragraph for the position explaining that verdict, from the same news `analyzeTicker` used (cached with it, so no extra Alpha Vantage call). The paragraph is cached 30 minutes per ticker, side and verdict.

All AI prompts live on the server (`lib/server/analysis.ts`). There's deliberately no generic prompt endpoint, so the OpenAI key can't be used as an open proxy. Shared helpers: `cachePromise` (`lib/server/cache.ts`; caches a promise per key, shared by concurrent callers; failures aren't kept), `fetchAlphaVantage` (starts requests at least 300ms apart across all routes, because Alpha Vantage rejects more than 5 a second with a "Burst pattern detected" `Information` reply), `fetchNews` (`NEWS_SENTIMENT` sorted latest first, as `{ title, summary, published, tickers: [{ ticker, relevance }] }`) and `fetchTickerNews` (hyphenated symbol, 404 when no relevant article), `askAnalyst` (system prompt plus OpenAI call) and `analyzeNews` (articles with their publication times, then the prompt), and `errorResponse`.

Error contract: `withUser` catches every handler's errors and calls `errorResponse`, which logs `METHOD path: message` and always returns `{ error: message }` with one of these statuses:
- 401: no signed-in user (`withUser`: no session, or an invalid or expired one).
- 502: a bad reply from Alpha Vantage, OpenAI, or the model. Alpha Vantage reports rate limits, missing entitlements and bad symbols with HTTP 200 and a `Note`/`Information`/`Error Message` body (or `{}`), so `fetchAlphaVantage` throws an `UpstreamError` whenever the expected key is missing. OpenAI SDK errors also map to 502.
- 400: a rejected request, such as a buy, short or withdrawal without enough available cash, or one during a margin call (`HttpError` with status 400; `UpstreamError` extends `HttpError`).
- 409: a Portfolio close (`close: true`) larger than the open position.
- 404: `/api/analysis/[ticker]` and `/api/portfolio/[ticker]/analysis` when the ticker has no news, or the latter when there's no open position (`UpstreamError` with an explicit status).
- 504: an upstream call timed out. Alpha Vantage times out at 30s (its response times vary widely), OpenAI at 30s with 1 retry, and the Postgres connection at 5s (in `lib/server/db.ts`).
- 500: anything else, such as database errors.

**Client** (React 19, App Router pages in `app/`: `/` (`app/page.tsx`), `/trading/[ticker]`, `/transactions`, `/portfolio`, `/deposit`, `/withdraw`; components in `components/`, all client components (`"use client"`) except a few presentational ones; each page renders `Header` and its main component):
- Auth (`@clerk/nextjs`): `app/layout.tsx` wraps the app in `ClerkProvider` (it reads `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`), and `components/AppShell.tsx` renders the pages inside `<Show when="signed-in">` with `SignInPage` (Clerk's `<SignIn>`, which links to sign-up) as the fallback, so no page loads while signed out. The header ends with Clerk's `<UserButton>` (profile, sign-out).
- API calls use axios with relative `/api/...` paths (`/api/rankings`, `/api/trading/${ticker}`, …), same origin, so Clerk's session cookie goes with them. Use axios rather than `fetch` so non-2xx responses throw.
- Navigation uses `next/link` (`href`) and `useRouter` from `next/navigation`. The logo is a static import of `public/AIStockTraderLogo.png` rendered with `next/image`. `CandlestickChart` loads `react-plotly.js` with `next/dynamic` and `ssr: false`, since Plotly needs `window` (Plotly 3 only takes `title: { text }`, not a string).
- Each fetching component keeps an `error` state and shows `apiErrorMessage(error)` (`lib/apiError.ts`: the response's `error`, or the request's own message) in place of its loading text.
- Home → `Rankings` calls `/api/rankings` and renders two presentational `StockRanking` tables. Trading → `TradingInterface` loads the time series (price, `BuySellFunctionality`, `CandlestickChart`), and `AIAnalysis` loads `/api/analysis/[ticker]` independently and shows the verdict above the paragraph.
- Portfolio → `PortfolioList` loads `/api/portfolio` and renders a `PortfolioRow` per position. Each row closes the position (SELL for longs, BUY to cover shorts) through `POST /api/trading/[ticker]`, then updates its quantity locally instead of refetching every price. The round AI button calls `/api/portfolio/[ticker]/analysis` only on first open, caches the result, and shows the verdict (Hold, Sell or Cover) above the paragraph. `QuantityStepper` is shared with `BuySellFunctionality`.
- Account: `AccountProvider` (`context/AccountContext.tsx`, inside `AppShell`, keyed by user ID so a new user gets a fresh one) loads `/api/account` once per signed-in user and exposes `{ account, error, refreshAccount }` through `useAccount()`, so the figures survive navigation. The header has three regions: logo and search, `AccountSummary` (Available, Equity, Unrealized P&L), and the page links plus Deposit/Withdraw pills. `BuySellFunctionality`, `PortfolioRow` and `TransferForm` call `refreshAccount()` after a successful POST. `AccountSummary` shows restricted cash under Available, and `MarginBanner` (under the header) shows a margin call and any buy-ins from the past week (dismissal remembered in `localStorage` per user). `BuySellFunctionality` disables Buy (unless the ticker is short) when the total exceeds Available, and Sell (unless the ticker is long) when half the total does; both during a margin call. The server stays authoritative for flips.
- Deposit/Withdraw pages render `TransferForm` with `direction="deposit" | "withdraw"`: method tiles, per-method fields with format checks (Luhn, expiry, CVC, ABA routing checksum, email; helpers in `lib/payments.ts`), and a `$` `QuantityStepper` (withdrawals capped at Available). Only `describeMethod`'s label and the amount are sent. Transactions merges `/api/transactions` and `/api/transfers` by date.
- Fractional orders: both trade forms have a `TradeModeToggle` (Shares | $) and an editable decimal `QuantityStepper` (6 decimals for shares, 2 for dollars). `toOrder` in `lib/orders.ts` turns the input into `{ quantity, total }`: a dollar amount becomes `amount / price` shares, and on the portfolio an amount that covers the whole position closes it exactly.
- Props are typed with TypeScript (no prop-types or `defaultProps`); put defaults in the destructured parameters. Parameter defaults don't apply to `null`.

**Styling:** Bootstrap 4.6 (the npm package's CSS, no Bootstrap JS) is imported first in `app/layout.tsx`, then `app/globals.css` (Tailwind's directives and base styles) and `app/App.css` (custom classes). Tailwind is v3 (`tailwind.config.ts`, `postcss.config.js`), with preflight disabled so Bootstrap keeps its base styles; v4's cascade layers would lose to Bootstrap's unlayered CSS. Class names shared by both libraries (`mt-5`, `py-4`, `mr-2`, `shadow-lg`) resolve to Tailwind's values, because Tailwind's CSS comes after Bootstrap's.

## Repo notes

- Each rankings refresh (the first home page load in 30 minutes) costs 1 Alpha Vantage call plus 1 OpenAI call, plus 1 of each per candidate checked (usually 14 to 20, up to 30, fewer when their analyses are already cached), and takes tens of seconds. Each trading page load costs 1 Alpha Vantage call (2 when its analysis isn't cached) plus 1 OpenAI call when it isn't cached, each portfolio page load costs 1 Alpha Vantage call per open position, each full app load (the header's `/api/account`) costs 1 Alpha Vantage call per open position, each trade or withdrawal that adds risk costs 1 call per open short (for the collateral check), and each portfolio AI button costs 1 OpenAI call (plus the ticker's analysis, 1 Alpha Vantage call and 1 OpenAI call, when it isn't cached) the first time it's opened in 30 minutes. Latest prices are cached for 60s (shared by `/api/account` and `/api/portfolio`), and rankings, ticker analyses and position analyses for 30 minutes; nothing else is, so this counts against the Alpha Vantage plan's rate limit (the free tier allows about 25 requests a day).
