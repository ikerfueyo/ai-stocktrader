# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

AI StockTrader is a mock-trading web app for U.S. common stocks (no ETFs, funds or OTC listings): a single Next.js 16 (App Router) app in TypeScript, with pages and API route handlers in one project, backed by PostgreSQL, with sign-in through Clerk; each user has their own account. Stock prices and news come from Alpha Vantage; buy/sell rankings and per-ticker analysis come from OpenAI (`gpt-6-luna`, reasoning off): the rankings from news sentiment, and each ticker's structured analysis from its news plus computed technicals, its earnings against estimates, estimate revisions and next report date, and its valuation and analyst consensus. The prompts ask for the likely price effect over the horizon (results against expectations, what's already priced in), not the tone of the news. A ticker only appears in a ranking when its own analysis agrees. Every fresh verdict is logged (`verdict_log`) and scored later against SPY (`GET /api/analysis/track-record`).

It's being turned into a simulated brokerage that follows Alpaca's Broker API and U.S. rules closely enough to switch to the real Alpaca later (phases in `docs/brokerage-roadmap.md`). Phase 0 (done) added the Broker types and interface (`lib/server/broker/`), the market-data layer with Alpaca's free data, the stock universe, extended-hours sessions and the job runner. Phase 1 (done) added brokerage accounts: onboarding with KYC review in the simulator (`SimBroker`), the account gate, Settings and the account switcher. Phase 2 (done) added funding: bank links, ACH and wire transfers with settlement, returns and fees in the simulator, and the Transfers, Deposit and Withdraw pages. Trading and positions still run on the original mock ledger below (keyed by user, one individual account each), which reads the simulator's cash activities for deposits and withdrawals, until the simulator's ledger replaces it in Phase 3.

## Commands

From the repo root:

- `npm install`: install dependencies
- `npm run dev`: dev server on http://localhost:3000 (pages and `/api/*`; Turbopack)
- `npm run build` / `npm start`: production build and server (`next start`)
- `npm test`: `node:test` (run through `tsx`) on `lib/kyc.test.ts` (the account application's rules: tax IDs, ages, addresses, disclosures, agreements), `lib/server/broker/sim/kyc.test.ts` (the simulator's review decisions and steps, reviewed profile changes, configurations, options approvals), `lib/server/broker/sim/shapes.test.ts` (the simulator's accounts, assets, calendar, clock, options approvals, bank links, recipient banks, transfers and activities checked against Alpaca's spec), `lib/server/broker/sim/funding.test.ts` (Fed banking days, ACH and wire timelines, test returns, instant credit, bank link and transfer rules), `lib/orders.test.ts` (turning order input into shares and a total), `lib/server/account.test.ts` (the cash, equity and unrealized P&L math, bid/ask fills, buy-ins, splits and dividends), `lib/server/orderMatching.test.ts` (when orders fill, trigger or expire, and reserved cash), `lib/server/history.test.ts` (equity history and time-weighted return), `lib/server/technicals.test.ts` (returns, moving averages, RSI, returns less SPY's), `lib/server/earnings.test.ts` (which quarters and estimates the analysis sees), `lib/server/trackRecord.test.ts` (verdict outcomes and hit rates), `lib/marketHours.test.ts` (the NYSE calendar, extended sessions and Alpaca's registered calendar), `lib/server/universe.test.ts` (which listings are tradable stocks), `lib/server/schedule.test.ts` (when daily jobs are due) and `lib/server/broker/conformance.test.ts` (objects checked against Alpaca's OpenAPI specs)
- `npm run lint`: ESLint (`eslint-config-next`, flat config in `eslint.config.mjs`); `npm run typecheck`: `tsc --noEmit`
- TypeScript is pinned to 6.x because typescript-eslint doesn't support TypeScript 7 yet.
- `npm run gen:alpaca-types`: regenerates the TypeScript types in `lib/server/broker/generated/` and `lib/server/marketData/generated/` from Alpaca's OpenAPI specs in `vendor/alpaca/` (`broker-api.json`, `trading-api.json`, `market-data-api.json`, downloaded from `https://docs.alpaca.markets/openapi/<name>.json`; refresh them there). It runs `openapi-typescript` through `npx`, since its TypeScript 5 peer dependency conflicts with the pinned 6.x. The generated files are lint-ignored; don't edit them.

## Setup

`.env.local` (gitignored, loaded by Next.js) needs `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME`, `ALPHA_VANTAGE_API_KEY`, `OPENAI_API_KEY`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY`, and optionally `ALPHA_VANTAGE_REQUESTS_PER_MINUTE` (the plan's limit, default 150), `SIMULATED_SPREAD_BPS` (default 5), `ORDER_MATCH_INTERVAL_MS` (default 30000) and `BACKGROUND_JOBS=off`, Alpaca's free market data (a Trading API account's paper keys, used for data only): `ALPACA_API_KEY_ID`, `ALPACA_API_SECRET_KEY`, `ALPACA_TRADING_URL` (default the paper API), `ALPACA_DATA_FEED` (`iex`, the free Basic plan's, or `sip` with Algo Trader Plus) and `ALPACA_REQUESTS_PER_MINUTE` (default 190; Basic allows 200), all optional (without the keys there are no asset flags, book or Alpaca calendar), `BROKER` (only `sim`, the default, for now), and for the simulator's reviews `SIM_KYC_SECONDS` (how long a submitted application or options request takes to decide, default 5) and `SIM_KYC_REVIEW_SECONDS` (a manual review or reviewed profile change, default 60), and for funding `SIM_FUNDING_FAST_SECONDS` (each transfer step takes this long instead of following the banking calendar; unset by default), `SIM_ACH_DAILY_LIMIT` (per transfer and banking day each way, default 50000), `SIM_INSTANT_DEPOSIT_LIMIT` (default 1000), `SIM_WIRE_FEE` and `SIM_ACH_RETURN_FEE` (default 25 each, not yet confirmed against Alpaca's fee schedule), and, for local testing only, `PRICE_OVERRIDES` and `MARKET_HOURS_OVERRIDE` (`open` or `closed`). The schema is in `db/schema.sql`: both tables have a `user_id` (the Clerk user ID, added by migration `005_user_id.sql`, which assigns existing rows to the user passed as `-v owner=user_...`), and every account query filters by it. A `transactions` table (`date` as `TIMESTAMPTZ`, `type` = `BUY`/`SELL`, `ticker`, `price`, `quantity`, `total`, and `reason`: NULL for the user's trades, `LIQUIDATION` for automatic buy-ins, added by migration `004_transactions_reason.sql`; `quote_time` and `fill_policy`, the quote a trade filled against and which side of it, `ASK`/`BID` quoted, `SIM_ASK`/`SIM_BID` simulated spread or `LAST`, NULL for older rows, and `price NUMERIC(18, 6)`/`total DECIMAL(14, 2)`, from migration `006_execution.sql`) and a `cash_activity` table, the cash ledger (added as `cash_transfers` by migration `003_cash_transfers.sql`, renamed by `007_cash_activity.sql`): `date` defaulting to `now()`, `type` = `DEPOSIT`/`WITHDRAW` (mock transfers) or `DIVIDEND_IN`/`DIVIDEND_OUT` (dividends received on longs, charged to shorts), `method` (a display label such as `Visa •••• 4242`, or the dividend's description), a positive `amount`, and for dividends `ticker` and `reference` (the ex-date; a partial unique index posts each at most once). An `orders` table (migration `008_orders.sql`) holds orders that don't fill right away: `side`, `order_type` (`MARKET` queued while the market is closed, `LIMIT`, `STOP`, `STOP_LIMIT`), `quantity` or (dollar-amount market orders only) `amount`, `limit_price`, `stop_price`, `time_in_force` (`DAY` with `expires_at`, the session close; `GTC`), `status` (`OPEN`, `FILLED`, `CANCELLED`, `EXPIRED`, `REJECTED`, with `status_reason`), `triggered_at` and `close_only` (a Portfolio close queued while the market is closed; migration `011_orders_close_only.sql`); a fill is a `transactions` row with `order_id`. A `watchlist` table (`user_id`, `ticker`, `added_at`; migration `009_watchlist.sql`) holds the tickers each user watches. A `verdict_log` table (migration `010_verdict_log.sql`, shared by all users) records each fresh ticker analysis: `ticker`, `verdict`, the newest close it saw (`price`, `price_date`), `generated_at`, `model` and `prompt_version` (`PROMPT_VERSION` in `lib/server/analysis.ts`; bump it when the prompts or inputs change, so the track record compares them). Migration 007 also adds `corporate_actions` (splits and dividends per ticker, shared by all users: `type` `SPLIT`/`DIVIDEND`, `ex_date`, `payment_date`, `factor`, `amount`) and `corporate_actions_checked` (when each ticker was last fetched). Read `DATE` columns as `::text`, since pg turns a `DATE` into a `Date` at the server's local midnight. `quantity` is `NUMERIC(18, 6)` for fractional shares, which `pg` returns as a string, so parse it before doing math. An `assets` table (migration `012_assets.sql`, shared by all users) holds the tradable universe: `symbol`, `name`, `exchange` and, from Alpaca, `alpaca_id`, `tradable`, `marginable`, `shortable`, `borrow_status`, `fractionable`, `margin_requirement_long`/`_short` (percentages) and `attributes` (NULL flags without Alpaca keys). Brokerage accounts (migration `013_accounts.sql`, which also emptied the mock ledger tables, resetting every user): `broker_accounts` maps each user to their accounts (`account_id`, `broker` `sim`/`alpaca`, `kind` `individual` (IRAs later), `account_number`); `account_attestations` keeps what the app records itself (`w9` with `{ backup_withholding }`, `form_crs`, `privacy_notice`, each with the time and IP). The simulator's tables: `sim_accounts` (Alpaca's account fields as JSONB, the tax ID masked to its last 4 digits, `status` and `status_due_at` for the next review step, `configurations`, `options_approved_level`, uploaded documents' metadata only), `sim_options_approvals` (decided at `due_at`) and `sim_events` (each event's ULID `id`, `account_id`, `stream` `trades`/`accounts`/`transfers`/`nta`, and the stream's payload). Funding (migration `014_funding.sql`): `sim_ach_relationships` (bank links, one queued or approved per account, account numbers masked to the last 4 digits, `status_due_at` for verification, `reason` the planned rejection), `sim_recipient_banks` (wire recipients), `sim_transfers` (`type` ach/wire, `direction`, Alpaca's `status`, `amount`, `instant_amount`, `fee`, `sent_at`/`complete_at` from the timeline, `return_at`/`return_code` for a deposit that comes back) and `sim_activities` (the account ledger: Alpaca activity IDs, `activity_type` CSD/CSW/FEE so far, a signed `net_amount`, `description`, `transfer_id`). Schema changes for existing databases go in `db/migrations/` as numbered `.sql` files, applied by hand with `psql -U postgres -d ai_stocktrader -f <file>`.

## Architecture

**Server** (route handlers in `app/api/**/route.ts`, all paths under `/api` because the pages use `/trading/[ticker]`, `/portfolio` and `/transactions`; logic in `lib/server/`, each module marked `server-only`):
- `lib/server/errors.ts`: `HttpError`, `UpstreamError`, `errorResponse` (the error contract below) and `withUser`, which wraps every handler: it reads the Clerk session with `auth()` (made available by `clerkMiddleware()` in `proxy.ts`, Next 16's name for middleware), answers 401 without a signed-in user, passes the user ID to the handler (every account query and `withAccountLock` take it), and turns thrown errors into error responses. So every route, including `/api/rankings` and `/api/analysis/[ticker]`, needs a signed-in user. Requests are same-origin, so the Clerk session cookie authenticates them; there's no CORS.
- `lib/server/broker/`: the brokerage the app will trade through. `types.ts` names Alpaca's Broker API objects (`Account`, `TradeAccount`, `Order`, `Position`, `Activity`, `Transfer`, `ACHRelationship`, `Asset`, `AccountDocument`, ...) from the generated types, snake_case with decimals as strings exactly as Alpaca returns them; `broker.ts` is the `Broker` interface, one method per Broker API endpoint, which the simulator (`SimBroker`, from Phase 1) and later `AlpacaBroker` implement, and `brokerMode()` (`BROKER`); `errors.ts` is `BrokerError` (Alpaca's `{ code, message }` with an HTTP status, an `HttpError`); `conformance.ts` validates objects against the vendored specs with Ajv (tests only, reads the files). `HttpError` itself is in `lib/server/httpError.ts` (not `server-only`, so pure modules can throw it); `errors.ts` re-exports it, and `errorResponse` recognizes it and its subclasses with `isHttpError` (its `isHttpError` marker as well as `instanceof`, since a module loaded twice has two copies of the class).
- The simulator (`lib/server/broker/sim/`, `getBroker()` in `lib/server/broker/index.ts` returns its `SimBroker`, created per module rather than with `singleton`: it keeps no state, and a `globalThis` instance outlived hot reloads and threw errors from stale classes): `accounts.ts` runs Alpaca's account endpoints on `sim_accounts` (create, get, update, close, document upload, configurations, options approval) and `emitEvent`; `kyc.ts` (pure) decides reviews (`decideApplication`: last name `Reject`, `ActionRequired` or `Review` picks the outcome for testing, and a control-person, affiliated or politically exposed disclosure always goes to manual review), steps them (`nextReviewStep`: SUBMITTED, then APPROVED and ACTIVE, or APPROVAL_PENDING, ACTION_REQUIRED (to review once a document is uploaded) or REJECTED; ACCOUNT_UPDATED back to ACTIVE), says which profile changes are reviewed (`updateNeedsReview`: address, name, citizenship, employer, a disclosure turning true), sets default configurations (`defaultConfigurations`: 2x margin and shorting only with the margin agreement) and checks changes (`configurationError`), and decides options approvals (`decideOptionsApproval`: a lower level without the experience); `shapes.ts` (pure) turns rows into Alpaca's objects (`toAccount`, `toAsset` with a name-based UUID when Alpaca gave none, `toCalendar`, `toClock`, `toOptionsApproval`). Reviews advance when due, from the `sim-accounts` job and whenever an account is read. `subscribe` polls `sim_events` every 2s. The Broker methods of later phases throw `BrokerError` 501. The application rules themselves are in `lib/kyc.ts` (shared with the onboarding form): `validateApplication` (U.S. tax residents 18 or older, citizens or permanent residents, at a residential U.S. address, a valid SSN (no 000, 666 or 9xx area) or ITIN, the disclosures' details when one is true, the customer and account agreements, the W-9 certification, Form CRS and the privacy notice delivered) and `maskTaxId`.
- Funding in the simulator: `funding.ts` (pure) has the Federal Reserve's holidays and banking days (`fedHolidays`, `isBankingDay`: banks close on Columbus and Veterans Days and open on Good Friday), `achTimeline` (to clearing at the 4:00 p.m. ET cutoff on a banking day, complete the next banking day at 9:00), `wireTimeline` (same banking day before 3:00 p.m.), `plannedReturn` (deposit cents .01, .02 or .10 come back 2 banking days after completing as R01, R02 or R10), `instantAmount`, the request checks (`relationshipRequestError`, `verifyRelationship`: the owner must be the account holder, an account number ending 0000 fails; `transferRequestError`: $1 minimum, the daily ACH limit, no incoming wires; `bankRequestError`: ABA only), `FUNDING_LIMITS` and `TRANSFER_FEES`. `transfers.ts` stores them: bank links (QUEUED, verified after `SIM_KYC_SECONDS`), recipient banks, transfers (`createTransfer`: an ACH deposit credits up to the instant limit at once as a CSD; `advanceTransfers` moves due ones: QUEUED to SENT_TO_CLEARING, when an outgoing transfer posts its CSW and any wire FEE; to COMPLETE, when a deposit posts the rest of its CSD; COMPLETE to RETURNED, posting a CSW for the whole deposit and the return FEE; `cancelTransfer` only while QUEUED, taking back any instant credit), `listActivities`, `ledgerCash` (the ledger's cash, queued withdrawals and unsettled instant credit) and `fastForwardTransfers` (dev). Every step emits `transfers` and `nta` events. The simulator doesn't check a withdrawal against the account's cash yet: the route does, on the mock ledger. Alpaca's `Activity` schema is a `oneOf` of two schemas without required fields, which no object can match, so activities are checked against `NonTradeActivity`.
- `lib/server/brokerAccounts.ts`: the user's accounts (`listAccounts`, with each one's status from the broker) and which one a request acts on (the `active_account` cookie when it's theirs and open, else the newest open one); `findUserAccount` (404 otherwise); `requireAccount(request, userId, purpose)`, which the trading, order and transfer POST routes call: trading and deposits need an ACTIVE or ACCOUNT_UPDATED account (and trading not suspended), withdrawals an ACTIVE one, else 403; `clientIp` (the IPv4 agreements are signed from). Status groups shared with the pages are in `lib/accounts.ts`.
- `lib/server/marketData/index.ts` is where the app gets market data: it re-exports everything in `lib/server/alphaVantage.ts` (Alpha Vantage premium stays the source of everything it has: the prices fills use, bars, news with sentiment, overviews, earnings, splits and dividends, search, market status) and adds Alpaca's free data from `lib/server/marketData/alpaca.ts` (`fetchAlpacaAssets`, cached 8 hours; `fetchAlpacaCalendar`, 24 hours; `fetchAlpacaClock`, 1 minute; `fetchQuoteBooks`, the top of book with sizes from multi-symbol snapshots, 15s; all through `fetchAlpaca`, which throws `AlpacaNotConfiguredError` (503) without keys) and `fetchQuoteWithBook`. Import market data from `@/lib/server/marketData`, not a provider, so a data type can move providers in one place. `lib/server/rateLimit.ts`'s `rateLimiter(name, spacingMs, perMinute)` spaces each provider's requests (Alpha Vantage 300ms and its per-minute limit, Alpaca 100ms and 190 a minute).
- Stock universe: `lib/server/universe.ts` (pure) `buildUniverse(listings, alpacaAssets)` keeps Alpha Vantage `LISTING_STATUS` rows with `assetType` Stock on NYSE, Nasdaq, NYSE American, NYSE Arca or Cboe BZX, drops warrants, units, rights, preferreds and notes (by name, and Nasdaq's fifth letters W, U and R), writes share classes with a dot (`BRK.B`), and with Alpaca keys also requires the stock on Alpaca's list and tradable there, taking its flags. `lib/server/assets.ts` stores it (`syncAssets`, the `assets` job), keeps it in memory (reloaded every 10 minutes) and answers `findAsset`, `requireTradableStock` (404 otherwise: the trading, order and watchlist routes and the Trading page's series) and `filterTradable` (search, rankings, movers). While the table is empty or missing (migration not applied, never synced) nothing is refused, with a warning.
- `lib/server/alphaVantage.ts`: Alpha Vantage calls (news, daily series, quotes and their caches, market status, splits and dividends, earnings: `fetchEarnings` (`EARNINGS`), `fetchEarningsEstimates` (`EARNINGS_ESTIMATES`) and `fetchNextReport` (`EARNINGS_CALENDAR`, a CSV endpoint, through `fetchAlphaVantageCsv`), each cached 12 hours per ticker). `lib/server/earnings.ts` is pure: `summarizeEarnings` picks the 4 latest reported quarters, the estimates for the quarter reported next and the 2 fiscal years from the one it ends in (with their 30- and 90-day revisions), and the next report date. `lib/server/corporateActions.ts`: `loadCorporateActions(tickers, refreshTickers)` returns the stored splits and dividends, first fetching any ticker never fetched (2 Alpha Vantage calls; a failure is logged and retried on a later request) and refreshing the open positions' tickers once a day, both before returning, so a split is in place before the account is valued or traded; tickers whose fetch failed are returned as `unsynced`, and `enforceCollateral` skips the buy-in while any position's ticker is. `lib/server/analysis.ts`: OpenAI calls (ticker and position analyses, rankings). `lib/server/portfolio.ts`: database-backed account helpers (`getAccount`, `getPositions`, `withAccountLock`, `enforceCollateral`). `lib/server/db.ts` exports a `pg` Pool. `lib/server/account.ts` holds the pure account math (`computePositions`, `valueAccount`, `assessTrade`, `assessWithdrawal`, `planBuyIn`), so it can be tested without a database.
- In-process state (the caches, the Alpha Vantage request spacing, last known prices, the per-user lock queues and the pg Pool) is created once on `globalThis` (`singleton` in `lib/server/cache.ts`), because Next.js can load a module more than once (dev hot reloads, separate route bundles). It's still per process, so the app must run as one long-lived Node server (`next start` or `next dev`), not as serverless functions. Account safety doesn't depend on that: `withAccountLock` also takes a Postgres advisory lock.
- Market hours: `lib/marketHours.ts` (shared with the pages) has the NYSE regular session (9:30 to 16:00 Eastern) and the extended sessions (pre-market from 4:00, after-hours until 20:00, 17:00 after an early close; `MarketStatus.extendedOpen`/`extendedClose`, and `sessionOn` returns both), with the 2026-2028 holidays and 1:00 p.m. early closes hard-coded from NYSE's published calendar (extend the lists when NYSE publishes the next one; outside them only weekends are known). On the server, Alpaca's calendar (a year back to two years ahead) is registered over the lists for the dates it covers (`registerCalendar`, from `lib/server/calendar.ts`'s `syncCalendar`, the `calendar` job, in every process), so unscheduled closures and later years are known; `settlementDate(day)` is its settlement date, else the next trading day (T+1). Overnight trading (20:00 to 4:00) isn't offered. `lib/server/market.ts`'s `getMarketStatus`/`isMarketOpen` also treat the market as closed when Alpha Vantage's `MARKET_STATUS` (cached 1 minute) reports the U.S. closed during a scheduled session, falling back to the calendar if it can't be fetched. `MARKET_HOURS_OVERRIDE` forces it.
- Orders: `lib/server/orderMatching.ts` is pure (`evaluateOrder`: a queued market order fills at the ask/bid; a limit fills when marketable, a buy when the ask is at or below the limit, a sell when the bid is at or above it, at the quote; a stop triggers when the last price reaches it, then fills as a market order, or for a stop-limit becomes a limit order, `triggered_at` kept; DAY orders expire at `expires_at` even while closed; an order placed before a split of its ticker is cancelled when matched, since its quantity and prices are in the old shares; nothing fills while closed or without a current quote. `reservedForOrders`: each open order that would open or add to a position holds back its cost (a buy) or half its value (a short) at its limit, else stop, else current price). `lib/server/orders.ts` runs it on stored orders: `matchOrders(userId, label, db)` fills through `assessTrade` with the other orders' reservations unavailable (a fill that isn't allowed rejects the order), caps a `close_only` order at the position then open on its closing side (rejected when there's none), records a stop's trigger even when its fill has to wait, treats a stale quote (`isStaleQuote`) as none, and judges each order at the time and market status after its quotes arrive, rechecked right before the fill, and `reservedCashFor`. `lib/server/upkeep.ts`'s `updateAccount` (dividends, buy-in check, then `matchOrders`) runs from `GET /api/account` and `GET /api/portfolio`, and from the background job: `instrumentation.ts` starts `lib/server/jobs.ts` in the Node runtime, which every 30s runs `updateAccount` for each user with open orders or a short (a negative raw share count, or any trade in a ticker that has split, since raw counts mix pre- and post-split shares) (the process holding a Postgres advisory lock is the only one that does), warming the quote cache with every ticker first. It reads `process.env` when it starts, so restart the dev server after changing the overrides. Orders are judged on prices sampled that often, so a briefer cross can be missed.
- Background jobs (`lib/server/jobs.ts`, started by `instrumentation.ts`): a check every `ORDER_MATCH_INTERVAL_MS` runs each due job in `JOBS`: `accounts` (the account upkeep described under Orders) on every check, `assets` at 4:30, 8:30 and 16:30 ET, `calendar` at 3:00 ET, `sim-accounts` (the simulator's due reviews and options decisions) and `sim-transfers` (due transfer steps) on every check, `settle-transfers` only from the dev route (every in-progress transfer one step now) (`isSlotDue` in `lib/server/schedule.ts`: a slot missed while the server was down runs when it's back; a failed run is retried on the next check). Leader-only jobs (all but `calendar`) run in the process holding the advisory lock; all run once right after startup. In development, `POST /api/dev/jobs` (`{ job }`, 404 in production) runs one now.
- Shapes shared with the pages (rows, `Account`, verdicts, request bodies) are in `lib/types.ts`.

Routes. Market data (prices, rankings, analyses) and its caches are shared by all users:
- `GET /api/analysis/[ticker]`: `analyzeTicker` fetches the ticker's latest news (dots become hyphens, since the news endpoint expects `BRK-A` where prices use `BRK.A`; articles below `MIN_NEWS_RELEVANCE` to the ticker are dropped) plus technicals computed from its full daily closes with its splits undone (`adjustForSplits`, from `loadCorporateActions`, so a split isn't read as a crash) (`computeTechnicals` in `lib/server/technicals.ts`: 5-session, 1-month and 3-month returns, the 1- and 3-month returns less SPY's (from SPY's compact series, shared with the performance chart), distance from the 50- and 200-day averages, 14-day RSI), its earnings and estimates (`summarizeEarnings`), and its company overview (valuation, analyst target price and rating counts), each left out when Alpha Vantage has none. The system prompt and `ANALYSIS_RULES` frame the task as the likely price effect over the horizon: whether the news is new or already reflected in the recent returns, results against expectations over tone, and an earnings report within the horizon as a catalyst and a risk. It returns `{ verdict, analysis, horizon, evidence, counterarguments, risks, catalysts, sources, generatedAt, dataAsOf, model }`: `BUY` (the evidence points to the price rising over the fixed 1-to-4-week horizon), `SELL` (falling; selling includes shorting) or `HOLD` (only when balanced or too thin); `analysis` is the thesis, one paragraph that must agree with the verdict; each list has 2 to 4 items; the model cites articles by number, and the server keeps only real ones as `sources` (title, link, time) and strips inline numbers from the text. No confidence percentages or price targets (JSON mode, temperature 0). Article numbers left in the text, in brackets or parentheses, are stripped. Cached per ticker for 30 minutes with its inputs (`publicAnalysis` leaves them out of the response). Each fresh verdict is inserted into `verdict_log` in the background (a failure is only logged). `peekTickerVerdict` reads a finished cached verdict without fetching.
- `GET /api/rankings`: `{ buy: [...], sell: [...] }`, up to 5 tickers each (`buildRankings`, cached 30 minutes). It fetches the latest 1000 market news articles, groups them by the companies each is mainly about (`mainTickers`: the most relevant tickers, so a bank's analyst note on another company isn't counted for the bank; crypto, forex, preferred, warrant, unit and rights symbols are skipped), and scores each stock from Alpha Vantage's per-ticker sentiment (sum / √articles). The 30 most bullish and 30 most bearish stocks (average sentiment at least ±0.15) go to one OpenAI call with their newest 4 articles each, and it shortlists up to 15 per side. Picking by coverage alone left the sell side nearly empty, since the most-covered stocks are mostly neutral or bullish. `confirmRankings` then runs `analyzeTicker` on the candidates in order and keeps only those whose verdict matches the side (`BUY` or `SELL`), so a side can have fewer than 5. Each refresh logs the funnel (articles, stocks, each candidate's verdict) to the server console. The listed tickers' cached analyses are kept at least as long as the rankings, so the Trading page shows the same verdict that put the stock in the ranking.
- `GET /api/analysis/track-record`: how logged verdicts turned out, per prompt version (newest first): for 5 and 20 sessions after each verdict's baseline close (`baselineDate`: the first session on or after both its `price_date` and the Eastern day of its `generated_at`, since its news can be newer than the cached closes it saw), per verdict the count, average price return, average return less SPY's between the same closes, and a hit rate (BUY: beat SPY; SELL: trailed it; HOLD: none). One verdict per prompt version, ticker and session (the last), only those at least 7 days old; splits are undone (`loadCorporateActions`, which fetches any ticker never fetched). Scored by `scoreVerdicts` (`lib/server/trackRecord.ts`, pure) and cached 12 hours.
- Accounts: `GET /api/accounts` (the user's accounts with status, newest first, and which is active); `POST /api/accounts` (`{ application }`, lib/kyc.ts's `AccountApplication`; 400 with the problems; the server signs the accepted agreements with the time and IP, creates the account at the broker, records the attestations and requests options approval when asked; 201 with Alpaca's Account); `GET`/`PATCH /api/accounts/[id]` (Alpaca's account; contact, identity except the tax ID and date of birth, disclosures, trusted contact and new agreements); `POST /api/accounts/[id]/close` (409 with positions, open orders or cash in the mock ledger); `GET`/`PATCH /api/accounts/[id]/configurations`; `POST /api/accounts/[id]/documents` (1 to 4 base64 files, 5 MB each); `GET`/`POST /api/accounts/[id]/options` (`{ level }`); `POST /api/accounts/active` (`{ accountId }`, sets the cookie). `GET /api/accounts/[id]`'s identity has the masked tax ID.
- `GET /api/quote/[ticker]`: the ticker's `Quote` (`fetchQuoteWithBook`): price, previous close, bid/ask, quote time and delay (`realtime`, or `end-of-day` once the price has reached the session close), the session's `open`/`high`/`low`/`volume` and `extendedHoursPrice` (Alpha Vantage's bulk quote; null from the daily-series fallback), and `book`, Alpaca's top of book with sizes and the last trade (`feed` `iex` or `sip`; null without keys or a current quote; only shown, never filled against). `GET /api/market`: `getMarketStatus()` (`{ open, session, extendedOpen, extendedClose, nextOpen, nextClose, earlyClose, calendarKnown }`).
- `GET /api/quote/[ticker]/earnings`: `summarizeEarnings` of the same three Alpha Vantage earnings calls the analysis uses (404 when all are empty). `GET /api/news/[ticker]`: up to 15 articles mainly about the ticker (`fetchTickerNews`, cached 5 minutes and shared with the analysis, filtered with `mainTickers`) with its sentiment and relevance; `NEWS_SENTIMENT`'s `time_published` is UTC (`parseNewsTime`). `GET /api/market/movers`: `fetchTopMovers` (`TOP_GAINERS_LOSERS`, realtime, cached 1 minute), up to 5 tradable stocks per list.
- `GET /api/quote/[ticker]/overview`: `fetchCompanyOverview` (Alpha Vantage `OVERVIEW`, cached 24 hours): name, exchange, sector, industry, market cap, P/E, forward P/E, dividend yield, beta, 52-week range and dividend dates, `null` where it has none; funds and unknown tickers get 404. `GET /api/trading/[ticker]/intraday?days=1..20`: the last sessions of 5-minute bars, pre-market and after-hours included (`fetchIntraday`, `TIME_SERIES_INTRADAY` with the entitlement, a month at a time, cached 60s). `GET /api/search?q=`: up to 8 tradable stocks from `SYMBOL_SEARCH` (`searchSymbols`, U.S. listings only, cached 24 hours per query, then type Equity and `filterTradable`; the trading and order routes reject a non-U.S. symbol (`isForeignListing`: an exchange suffix such as `.LON`) with 400, since trades are in dollars on NYSE hours).
- `GET /api/watchlist`: the user's watched tickers, newest first, with price and previous close (`fetchQuotes`) and the AI verdict only if one is already cached (`peekTickerVerdict`, so watching never triggers an analysis). `POST /api/watchlist` (`{ ticker }`; 400 past 50 tickers), `GET /api/watchlist/[ticker]` (`{ watched }`, no prices) and `DELETE /api/watchlist/[ticker]`.
- `GET /api/trading/[ticker]`: Alpha Vantage `TIME_SERIES_DAILY` (full history), passed through as is. Every price request sends `entitlement=realtime`, because even premium keys get only end-of-day data without it; there's no delayed fallback. The newest bar is today's partial day, and its close is the price shown and traded. A key without the realtime entitlement gets a `Note` back, which fails the request (502). Alpha Vantage replies with an empty `{}` both for unknown symbols and during its own price-data outages, and the two can't be told apart.
- `POST /api/trading/[ticker]`: body `{ order: { type, quantity | amount }, close? }`, a market order for a number of shares or a dollar amount. While the market is open the server fills it from its own quote, never from the request (the market status is read inside the account lock, after the quote): buys at the ask, sells at the bid (`fillPrice`), turns an amount into shares with `toOrder`, stamps `now()`, records `quote_time`/`fill_policy`, and returns `{ fill }`. While it's closed, the order is checked at the current price and queued as a DAY `MARKET` order for the open, returning `{ order }`. Trades that only reduce a position (covers, sales of longs) are always allowed and are paid from total cash, restricted included. Anything that opens or adds to a position, including the new side of a flip, goes through `assessTrade`: replayed with the trade added, it must leave no collateral shortfall. So a buy needs its cost in available cash (which excludes what open orders reserve) and a new short needs 50% of its value; during a margin call neither is allowed (400). A short without a current price blocks these with 502. `close: true` (the Portfolio page) returns 409 instead of flipping when the trade is larger than the open position or the position is gone, such as after a buy-in; a closing dollar amount that covers the whole position closes it exactly. A close queued while the market is closed is stored `close_only`, so it can't flip the position when it fills. The buy-in check runs after the insert.
- `POST /api/orders`: body `{ order: { ticker, side, orderType: LIMIT | STOP | STOP_LIMIT, quantity, limitPrice?, stopPrice?, timeInForce: DAY | GTC } }`, accepted at any time. A stop must be on the right side of the current price (400 otherwise). An order that opens or adds to a position is checked with `assessTrade` as if it filled at its limit (or stop), with the other open orders' reservations unavailable. While the market is open it's matched right away, so a marketable order fills at once. Returns `{ order }`. `GET /api/orders?status=open|all&ticker=`: newest first (`open` matches them first). `DELETE /api/orders/[id]`: cancels an open order (404 not the user's, 409 no longer open).
- `GET /api/portfolio/history?range=1W|1M|3M|YTD|1Y|ALL`: daily equity rebuilt from the trades, cash ledger, splits and each traded ticker's daily closes (`fetchDailyCloses`, `compact` or `full` depending on how far back the first activity is, cached 12 hours), by `equityHistory` (`lib/server/history.ts`), with the time-weighted return (each day's return with the deposits and withdrawals since the previous trading day taken out, weekends and holidays included, chained; dividends count as return; each day is valued with that day's splits, not the next day's (`computePositions`' `splitsThrough`)) and SPY's price return, both measured from the range's first day. A return is only meaningful with positive equity, so a day that starts or ends at zero or below adds nothing and is a gap on the chart (`twr: null`). The range totals are `twr` and `benchmarkReturn`. There's no 1D range.
- `GET /api/transactions`: all rows, newest first, each with `realized_pnl` (`id` breaks ties for rows migrated from the old `DATE` column, which all sit at midnight)
- `GET /api/portfolio`: open positions `[{ ticker, quantity, avgCost, price, bid, ask, error }]`, computed from `transactions` by `computePositions` (no positions table), with the traded tickers' splits applied in date order (before the first trade on or after a split's date: shares × factor, average cost ÷ factor, so cost basis and cash don't change). Every replay of stored trades (`getAccount`, `getPositions`) goes through the splits; `assessTrade` takes them too. The replay also books realized P&L on the part of each trade that reduces or closes a position, against its average cost (`realizedPnl`, and per transaction). Rows include `previousClose`, for the Today column. `quantity` is signed: Trading-page sells past zero are intentional shorts, so a negative position is a short. Cost basis is average cost: adding to a position re-averages it, reducing it keeps the average, and a trade that flips the side opens the remainder at the trade price. Quantities are rounded to 6 decimals after each trade (`roundShares`), so float drift can't leave a tiny position open. Rows also carry `bid`/`ask`. Prices come from `fetchQuotes` (`lib/server/alphaVantage.ts`), with `Promise.allSettled`, so a ticker whose price fails gets `price: null` and an `error` instead of failing the whole response. `fetchQuotes` fetches every uncached ticker together with the premium bulk endpoints (`REALTIME_BULK_QUOTES` plus `REALTIME_BULK_BID_ASK_PRICES`, 100 symbols per call); a plan without them gets artificial sample data with a "premium endpoint" `message`, which `fetchAlphaVantage` turns into a `NotEntitledError`, and the endpoint is then skipped for an hour in favor of each ticker's compact `TIME_SERIES_DAILY` (same entitlement and newest-bar close as `/api/trading/[ticker]`, previous bar for the previous close). The current key's plan includes them. Without quoted bid/ask, a simulated spread of `SIMULATED_SPREAD_BPS` basis points (at least a cent, at most half the price so the bid stays positive; 0 turns it off and fills at the last price) is centered on the last price. Each ticker's quote is cached for 15s (failures aren't kept), so `/api/portfolio`, `/api/account` and trades share one call. The last price is remembered in memory, which `fetchPrices` falls back to (listing the ticker in `staleTickers`) when a fetch fails. `PRICE_OVERRIDES` (env JSON such as `{"TSTA": 120}`) fixes prices without Alpha Vantage, with no spread, for local testing only.
- `GET /api/account`: `{ totalCash, availableCash, restrictedCash, reservedCash, realizedPnl, netDividends, collateralRequirement, collateralShortfall, collateralRatio, shortLiability, marginStatus, equity, unrealizedPnl, missingPrices, positions: [{ ticker, quantity }], liquidations, pendingTransferOut, withdrawableCash }` for the header (`liquidations`: the past week's buy-in trades; `withdrawableCash`: available cash less instant deposit credit not yet settled). The cash model (`valueAccount`):
  - Total cash is a plain ledger: net cash activity plus every sell's total minus every buy's, so a short sale's proceeds land in it and a cover pays from it. It starts from all past trades. Net cash activity (`getAccount`) is the broker's cash activities for the user's accounts (`ledgerCash`, after advancing their due transfers: deposits as they're credited, withdrawals when they leave, fees) plus the mock ledger's dividends, less queued withdrawals (`pendingTransferOut`), which are held from the moment they're requested.
  - Dividends (`postDividends`, from `updateAccount`): `planDividends` finds each stored dividend whose payment date has come, on a ticker held at its ex-date's open (`positionsAt`: trades before that day, splits through it), not yet posted, and it's inserted into `cash_activity` dated at the payment date's close. Longs receive shares × amount, shorts pay it.
  - Short collateral: 150% of the shorts' current market value (`SHORT_COLLATERAL_RATE`) is restricted cash; the rest of total cash, less the cash reserved for open orders, is available cash, never negative. When total cash can't meet the requirement, the gap is `collateralShortfall` (the deposit that would make the account compliant, including any negative cash). `marginStatus` is `ok`, `margin_call` (shortfall), or `buy_in` (total cash below 130% of short liability, `BUY_IN_RATE`).
  - `equity = total cash + Σ long market value - Σ short market liability` (also net deposits + realized + unrealized P&L + net dividends; the tests check it), and `unrealizedPnl = Σ long (market value - cost basis) + Σ short (sale proceeds - market liability)`, with cost basis and proceeds at `avgCost × shares`. Collateral only splits total cash, so it changes neither. Trades at the market price never change equity; the tests check this.
  - A position without a current price is valued at its last known price, or at its cost, and listed in `missingPrices`. Stale prices never approve a risky action or trigger a buy-in. During a scheduled session (the NYSE calendar), a quote that's end-of-day or more than 15 minutes old (`isStaleQuote`) counts as stale too: `fetchPrices` lists it in `staleTickers` (it's still shown), and a market order on it fails with 502. `insertTrade` refuses a fill without a positive price and quantity.
  - Automatic buy-in (`planBuyIn`, run by `enforceCollateral`): below 130%, every short is covered by the same fraction, just enough to restore 150% (it takes $2 of covers per $1 of shortfall, a little more at the ask), and longs are sold pro rata only if covering every short leaves negative cash. Covers fill at the ask and sales at the bid. Prices only arrive with requests, so it runs lazily, from `GET /api/account`, `GET /api/portfolio` (both through `updateAccount`, which posts dividends first) and after each trade, and only while the market is open; those GETs can write. Each user's account changes run one at a time through `withAccountLock(userId, fn)`: an in-process queue per user in front of a Postgres advisory lock (`pg_advisory_lock(hashtext(user_id))`) on a dedicated pool client, which `fn` gets and must use for its queries (`getAccount`, `insertTrade`, `inTransaction`). The client is held for the whole call, Alpha Vantage requests included, so the pool allows 20 connections.
- Funding: `GET`/`POST /api/accounts/[id]/ach` (bank links; Alpaca's CreateACHRelationshipRequest; 409 with another active link) and `DELETE .../ach/[relationshipId]` (422 with transfers in progress); `GET`/`POST /api/accounts/[id]/banks` (`{ name, bank_code, account_number }`, ABA only) and `DELETE .../banks/[bankId]`; `GET /api/accounts/[id]/transfers` (Alpaca's Transfers, newest first; `expires_at` is when the money is expected) and `POST` (`{ transfer: { type: ach | wire, direction, amount, relationshipId | bankId } }`; the active account only (409 otherwise), checked with `requireAccount`; a withdrawal goes through `assessWithdrawal` on the mock ledger inside the account lock, for the amount plus any wire fee, with unsettled instant credit excluded; 201); `DELETE .../transfers/[transferId]` (cancel while QUEUED); `GET /api/funding` (`FundingTerms`: minimum, daily ACH limit, instant limit, wire and return fees). IDs that aren't UUIDs get 404 (or 422 in a body) before any query.
- `GET /api/transfers`: the user's cash ledger, newest first (`loadCashActivity`: the broker's CSD, CSW and FEE activities as DEPOSIT, WITHDRAW and FEE rows, with the mock ledger's dividends); `POST` is gone (405). The performance history reads the same ledger: deposits and withdrawals are external flows, fees count against the return.
- `GET /api/portfolio/[ticker]/analysis`: the same shape for an open position (404 if there's none). `analyzePosition` derives the verdict from the ticker's `analyzeTicker` verdict, so it can't contradict the Trading page: a long is `SELL` on `SELL` and `HOLD` otherwise, a short is `COVER` on `BUY` and `HOLD` otherwise. A second OpenAI call (temperature 0) then writes the structured analysis for the position explaining that verdict, from the same inputs `analyzeTicker` used (cached with it, so no extra Alpha Vantage call) plus the position: shares, average cost, unrealized P&L and weight in the account's equity (the route values the account with the cached quotes). Cached 30 minutes per user, ticker, side and verdict.

All AI prompts live on the server (`lib/server/analysis.ts`). There's deliberately no generic prompt endpoint, so the OpenAI key can't be used as an open proxy. Shared helpers: `cachePromise` (`lib/server/cache.ts`; caches a promise per key, shared by concurrent callers; failures aren't kept), `fetchAlphaVantage` (starts requests at least 300ms apart and at most `ALPHA_VANTAGE_REQUESTS_PER_MINUTE` in any 61 seconds across all routes, queuing the rest, because Alpha Vantage rejects more than 5 a second with a "Burst pattern detected" `Information` reply and more than the plan's per-minute limit, which can still trip during a long run of calls, so it's retried up to twice after a pause), `fetchNews` (`NEWS_SENTIMENT` sorted latest first, as `{ title, summary, published, tickers: [{ ticker, relevance }] }`) and `fetchTickerNews` (hyphenated symbol, 404 when no relevant article), `askAnalyst` (system prompt plus OpenAI call) and `analyzeNews` (articles with their publication times, then the prompt), and `errorResponse`.

Error contract: `withUser` catches every handler's errors and calls `errorResponse`, which logs `METHOD path: message` and always returns `{ error: message }` with one of these statuses:
- 401: no signed-in user (`withUser`: no session, or an invalid or expired one).
- 502: a bad reply from Alpha Vantage, OpenAI, or the model. Alpha Vantage reports rate limits, missing entitlements and bad symbols with HTTP 200 and a `Note`/`Information`/`Error Message` body (or `{}`), so `fetchAlphaVantage` throws an `UpstreamError` whenever the expected key is missing. OpenAI SDK errors also map to 502.
- 400: a rejected request, such as a buy, short or withdrawal without enough available cash, or one during a margin call (`HttpError` with status 400; `UpstreamError` extends `HttpError`).
- 403: no open brokerage account, or one whose status doesn't allow it (`requireAccount`).
- 409: a Portfolio close (`close: true`) larger than the open position; applying while the user has an open account; closing an account with positions, open orders or cash.
- 422 (and other `BrokerError` statuses): the broker refused the request, such as an invalid application or configuration; 501 for a Broker method a later phase implements.
- 404: `/api/analysis/[ticker]` and `/api/portfolio/[ticker]/analysis` when the ticker has no news, or the latter when there's no open position (`UpstreamError` with an explicit status); a ticker outside the universe; an account that isn't the user's.
- 504: an upstream call timed out. Alpha Vantage times out at 30s (its response times vary widely), OpenAI at 30s with 1 retry, and the Postgres connection at 5s (in `lib/server/db.ts`).
- 500: anything else, such as database errors.

## Repo notes

- Each rankings refresh (the first home page load in 30 minutes) costs 1 Alpha Vantage call plus 1 OpenAI call, plus 1 of each per candidate checked (usually 14 to 20, up to 30, fewer when their analyses are already cached), and takes tens of seconds. Each trading page load costs 2 Alpha Vantage calls, the full series and the quote (the quote is shared with the 15s cache), plus its news every 5 minutes (shared with its analysis), the company overview once a day and its 3 earnings calls every 12 hours per ticker (shared with the analysis), and 1 Alpaca snapshot call per 15s with Alpaca keys and 1 intraday call per 60s when the 1D or 5D chart is opened; each new search query costs 1 call (cached a day); the home page's movers cost 1 call a minute; the stock universe costs 1 Alpha Vantage call (`LISTING_STATUS`, cached 6 hours) and 1 Alpaca call per sync, 3 times a day, and the calendar 1 Alpaca call a day; the watchlist costs 1 call per ticker per 15s (1 in all with the bulk endpoints) plus 1 OpenAI call when it isn't cached, each portfolio page load costs 1 Alpha Vantage call per open position (plus, for the performance chart, 1 per ticker ever traded and 1 for SPY every 12 hours), each full app load (the header's `/api/account`) costs 1 Alpha Vantage call per open position (plus 2 per traded ticker the first time it's seen, and 2 per open position once a day, for splits and dividends), each trade or withdrawal that adds risk costs 1 call per open short (for the collateral check), and the background job costs 1 call per ticker with open orders or shorts per run, every 30s, while the market is open (shared with the 15s quote cache; 1 call in all with the bulk endpoints), each portfolio AI button costs 1 OpenAI call (plus the ticker's analysis when it isn't cached) the first time it's opened in 30 minutes. Latest quotes are cached for 15s (shared by `/api/account`, `/api/portfolio`, `/api/quote` and trades), the market status for 1 minute (only checked during scheduled sessions), and with the bulk endpoints a whole portfolio costs 1 call (2 with bid/ask) instead of 1 per position, and rankings, ticker analyses and position analyses for 30 minutes; nothing else is, so this counts against the Alpha Vantage plan's rate limit (the current plan allows 150 requests a minute; a rankings refresh can use most of a minute's worth, and later calls wait their turn).
