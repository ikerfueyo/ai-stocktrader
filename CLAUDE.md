# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

AI StockTrader is a mock-trading web app: a Create React App frontend (`client/`) and an Express backend (`server/`) backed by PostgreSQL, with sign-in through Clerk; each user has their own account. Stock prices and news come from Alpha Vantage; buy/sell rankings and per-ticker analysis come from OpenAI (`gpt-6-luna`, reasoning off) sentiment analysis of news titles/summaries, and a ticker only appears in a ranking when its own analysis agrees.

## Commands

From the repo root:

- `npm run install-all`: install `client/` and `server/` dependencies
- `npm start`: run client (port 3000) and server (port 5001, via `node --watch`) together with `concurrently`

Per package:

- Client: `npm start --prefix client`, `npm run build --prefix client`, `npm test --prefix client` (Jest via react-scripts; single test: `npm test --prefix client -- -t "<name>"` or pass a file path). There are currently no test files.
- Server: `npm start --prefix server` (`node --watch`, restarts on changes to `index.js` and the modules it requires) or `node server/index.js`. `npm test --prefix server` runs `node --test` (built in, no dependencies) on `server/account.test.js`, which covers the cash, equity and unrealized P&L math.
- Linting is CRA's built-in ESLint (`react-app` config), which runs during `npm start`/`build`. There is no standalone lint script.

## Setup

`server/.env` (gitignored) needs `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME`, `ALPHA_VANTAGE_API_KEY`, `OPENAI_API_KEY`, `CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY` (the server won't start without the Clerk keys), and optionally `ALPHA_VANTAGE_ENTITLEMENT` and `CLIENT_ORIGIN` (the CORS origin, default `http://localhost:3000`). `client/.env` (gitignored) needs `REACT_APP_CLERK_PUBLISHABLE_KEY`, the same publishable key. The schema is in `server/db.sql`: both tables have a `user_id` (the Clerk user ID, added by migration `005_user_id.sql`, which assigns existing rows to the user passed as `-v owner=user_...`), and every account query filters by it. A `transactions` table (`date` as `TIMESTAMPTZ`, `type` = `BUY`/`SELL`, `ticker`, `price`, `quantity`, `total`, and `reason`: NULL for the user's trades, `LIQUIDATION` for automatic buy-ins, added by migration `004_transactions_reason.sql`) and a `cash_transfers` table for mock deposits and withdrawals (`date` defaulting to `now()`, `type` = `DEPOSIT`/`WITHDRAW`, `method`, a display label such as `Visa •••• 4242`, and `amount`; added by migration `003_cash_transfers.sql`). `quantity` is `NUMERIC(18, 6)` for fractional shares, which `pg` returns as a string, so parse it before doing math. Schema changes for existing databases go in `server/migrations/` as numbered `.sql` files, applied by hand with `psql -U postgres -d ai_stocktrader -f <file>`.

## Architecture

**Server** (`server/index.js`, all routes in one file. Auth: `clerkMiddleware()` and then `requireUser` run before every route, so every route, including `/rankings` and `/analysis/:ticker`, needs a signed-in user (401 otherwise); `requireUser` sets `req.userId`, which every account query and `withAccountLock` take. Market data (prices, rankings, analyses) and its caches are shared by all users; `server/db.js` exports a `pg` Pool; `server/account.js` holds the pure account math (`computePositions`, `valueAccount`, `assessTrade`, `assessWithdrawal`, `planBuyIn`), so it can be tested without a database):
- `GET /analysis/:ticker`: `analyzeTicker` fetches the ticker's latest news (dots become hyphens, since the news endpoint expects `BRK-A` where prices use `BRK.A`; articles below `MIN_NEWS_RELEVANCE` to the ticker are dropped) and returns `{ verdict, analysis }`: `BUY` (news points to the price rising), `SELL` (falling; selling includes shorting) or `HOLD` (only when balanced or too thin), and a one-paragraph explanation that must agree with it (JSON mode, temperature 0). Cached per ticker for 30 minutes.
- `GET /rankings`: `{ buy: [...], sell: [...] }`, up to 5 tickers each (`buildRankings`, cached 30 minutes). It fetches the latest 1000 market news articles, groups them by the companies each is mainly about (`mainTickers`: the most relevant tickers, so a bank's analyst note on another company isn't counted for the bank; crypto, forex, preferred, warrant, unit and rights symbols are skipped), and scores each stock from Alpha Vantage's per-ticker sentiment (sum / √articles). The 30 most bullish and 30 most bearish stocks (average sentiment at least ±0.15) go to one OpenAI call with their newest 4 articles each, and it shortlists up to 15 per side. Picking by coverage alone left the sell side nearly empty, since the most-covered stocks are mostly neutral or bullish. `confirmRankings` then runs `analyzeTicker` on the candidates in order and keeps only those whose verdict matches the side (`BUY` or `SELL`), so a side can have fewer than 5. Each refresh logs the funnel (articles, stocks, each candidate's verdict) to the server console. The listed tickers' cached analyses are kept at least as long as the rankings, so the Trading page shows the same verdict that put the stock in the ranking.
- `GET /trading/:ticker`: Alpha Vantage `TIME_SERIES_DAILY` (full history), passed through as is. It sends `entitlement=ALPHA_VANTAGE_ENTITLEMENT` (default `delayed`), because even premium keys get only end-of-day data without it. With the entitlement, the newest bar is today's partial day, and its close is the price shown and traded. A key without that entitlement gets a `Note` back. Alpha Vantage replies with an empty `{}` both for unknown symbols and during its own price-data outages, and the two can't be told apart.
- `POST /trading/:ticker`: body `{ transaction: {...}, close? }`, inserts into `transactions`. Trades that only reduce a position (covers, sales of longs) are always allowed and are paid from total cash, restricted included. Anything that opens or adds to a position, including the new side of a flip, goes through `assessTrade`: replayed with the trade added, it must leave no collateral shortfall. So a buy needs its cost in available cash and a new short needs 50% of its value; during a margin call neither is allowed (400). A short without a current price blocks these with 502. `close: true` (the Portfolio page) returns 409 instead of flipping when the trade is larger than the open position, such as after a buy-in. The buy-in check runs after the insert.
- `GET /transactions`: all rows, newest first (`id` breaks ties for rows migrated from the old `DATE` column, which all sit at midnight)
- `GET /portfolio`: open positions `[{ ticker, quantity, avgCost, price, error }]`, computed from `transactions` by `computePositions` (no positions table). `quantity` is signed: Trading-page sells past zero are intentional shorts, so a negative position is a short. Cost basis is average cost: adding to a position re-averages it, reducing it keeps the average, and a trade that flips the side opens the remainder at the trade price. Quantities are rounded to 6 decimals after each trade (`roundShares`), so float drift can't leave a tiny position open. Prices come from `TIME_SERIES_DAILY` (`compact`, same entitlement and newest-bar close as `/trading/:ticker`), fetched in parallel with `Promise.allSettled`, so a ticker whose price fails gets `price: null` and an `error` instead of failing the whole response. `fetchLatestPrice` caches each ticker's price promise for 60s (failures aren't kept), so `/portfolio` and `/account` share one Alpha Vantage call per ticker. It also remembers each ticker's last price in memory, which `fetchPrices` falls back to (listing the ticker in `staleTickers`) when a fetch fails. `PRICE_OVERRIDES` (env JSON such as `{"TSTA": 120}`) fixes prices without Alpha Vantage, for local testing only.
- `GET /account`: `{ totalCash, availableCash, restrictedCash, collateralRequirement, collateralShortfall, collateralRatio, shortLiability, marginStatus, equity, unrealizedPnl, missingPrices, positions: [{ ticker, quantity }], liquidations }` for the header (`liquidations`: the past week's buy-in trades). The cash model (`valueAccount`):
  - Total cash is a plain ledger: net transfers plus every sell's total minus every buy's, so a short sale's proceeds land in it and a cover pays from it. It starts from all past trades.
  - Short collateral: 150% of the shorts' current market value (`SHORT_COLLATERAL_RATE`) is restricted cash; the rest of total cash is available cash, never negative. When total cash can't meet the requirement, the gap is `collateralShortfall` (the deposit that would make the account compliant, including any negative cash). `marginStatus` is `ok`, `margin_call` (shortfall), or `buy_in` (total cash below 130% of short liability, `BUY_IN_RATE`).
  - `equity = total cash + Σ long market value - Σ short market liability`, and `unrealizedPnl = Σ long (market value - cost basis) + Σ short (sale proceeds - market liability)`, with cost basis and proceeds at `avgCost × shares`. Collateral only splits total cash, so it changes neither. Trades at the market price never change equity; the tests check this.
  - A position without a current price is valued at its last known price, or at its cost, and listed in `missingPrices`. Stale prices never approve a risky action or trigger a buy-in.
  - Automatic buy-in (`planBuyIn`, run by `enforceCollateral`): below 130%, every short is covered by the same fraction, just enough to restore 150% (it takes $2 of covers per $1 of shortfall), and longs are sold pro rata only if covering every short leaves negative cash. Prices only arrive with requests, so it runs lazily, from `GET /account`, `GET /portfolio` and after each trade; those GETs can write. Each user's account changes run one at a time through `withAccountLock(userId, fn)`, an in-process queue per user (it assumes one server process).
- `POST /transfers`: body `{ transfer: { type, method, amount } }`, inserts into `cash_transfers` (the server sets the date). 400 for a bad type, an empty method, an amount outside $0.01 to $99,999,999.99, or a withdrawal above the available cash (`assessWithdrawal`; withdrawals never come from short collateral and are blocked during a margin call). Deposits skip the lock and the buy-in check, so a deposit meant to meet a margin call counts first.
- `GET /transfers`: all deposits and withdrawals, newest first
- `GET /portfolio/:ticker/analysis`: `{ analysis }`, a hold-or-sell take for longs, or keep-short-or-cover for shorts (the server picks the prompt from the position; 404 if there's no open position)

All AI prompts live on the server (`/rankings`, `/analysis/:ticker`). There's deliberately no generic prompt endpoint, so the OpenAI key can't be used as an open proxy. Shared helpers: `cachePromise` (caches a promise per key, shared by concurrent callers; failures aren't kept), `fetchAlphaVantage` (starts requests at least 300ms apart across all routes, because Alpha Vantage rejects more than 5 a second with a "Burst pattern detected" `Information` reply), `fetchNews` (`NEWS_SENTIMENT` sorted latest first, as `{ title, summary, published, tickers: [{ ticker, relevance }] }`) and `fetchTickerNews` (hyphenated symbol, 404 when no relevant article), `askAnalyst` (system prompt plus OpenAI call) and `analyzeNews` (articles with their publication times, then the prompt), and `sendError`.

Error contract: every route's `catch` calls `sendError`, which logs `METHOD url: message` and always returns `{ error: message }` with one of these statuses:
- 401: no signed-in user (`requireUser`: no session token, or an invalid or expired one).
- 502: a bad reply from Alpha Vantage, OpenAI, or the model. Alpha Vantage reports rate limits, missing entitlements and bad symbols with HTTP 200 and a `Note`/`Information`/`Error Message` body (or `{}`), so `fetchAlphaVantage` throws an `UpstreamError` whenever the expected key is missing. OpenAI SDK errors also map to 502.
- 400: a rejected request, such as a buy, short or withdrawal without enough available cash, or one during a margin call (`HttpError` with status 400; `UpstreamError` extends `HttpError`).
- 409: a Portfolio close (`close: true`) larger than the open position.
- 404: `/analysis/:ticker` and `/portfolio/:ticker/analysis` when the ticker has no news, or the latter when there's no open position (`UpstreamError` with an explicit status).
- 504: an upstream call timed out. Alpha Vantage times out at 30s (its response times vary widely), OpenAI at 30s with 1 retry, and the Postgres connection at 5s (in `db.js`).
- 500: anything else, such as database errors.

**Client** (React 19, react-router v7; routes in `client/src/App.js`: `/`, `/trading/:ticker`, `/transactions`, `/portfolio`, `/deposit`, `/withdraw`):
- Auth (`@clerk/react`; `@clerk/clerk-react` is the deprecated older name): `ClerkProvider` wraps the app in `index.js`, and an axios request interceptor there adds `Authorization: Bearer <getToken()>` to every API call. `App.js` renders the routes inside `<Show when="signed-in">` with `SignInPage` (Clerk's `<SignIn>`, which links to sign-up) as the fallback, so no page loads while signed out. The header ends with Clerk's `<UserButton>` (profile, sign-out).
- API calls use axios with relative paths (`/rankings`, `/trading/${ticker}`, …). The CRA dev server proxies them to `localhost:5001` via the `"proxy"` field in `client/package.json`. Don't hardcode the backend URL, and use axios rather than `fetch` so non-2xx responses throw.
- Each fetching component keeps an `error` state and shows `error.response?.data?.error ?? error.message` in place of its loading text.
- Home → `Rankings` calls `/rankings` and renders two presentational `StockRanking` tables. Trading → `TradingInterface` loads the time series (price, `BuySellFunctionality`, `CandlestickChart`), and `AIAnalysis` loads `/analysis/:ticker` independently and shows the verdict above the paragraph.
- Portfolio → `PortfolioList` loads `/portfolio` and renders a `PortfolioRow` per position. Each row closes the position (SELL for longs, BUY to cover shorts) through `POST /trading/:ticker`, then updates its quantity locally instead of refetching every price. The round AI button calls `/portfolio/:ticker/analysis` only on first open and caches the result. `QuantityStepper` is shared with `BuySellFunctionality`.
- Account: `AccountProvider` (`client/src/context/AccountContext.js`, wrapping `<App />` in `index.js`) loads `/account` once per signed-in user (cleared on sign-out or a user change) and exposes `{ account, error, refreshAccount }` through `useAccount()`, so the figures survive navigation. The header has three regions: logo and search, `AccountSummary` (Available, Equity, Unrealized P&L), and the page links plus Deposit/Withdraw pills. `BuySellFunctionality`, `PortfolioRow` and `TransferForm` call `refreshAccount()` after a successful POST. `AccountSummary` shows restricted cash under Available, and `MarginBanner` (under the header) shows a margin call and any buy-ins from the past week (dismissal remembered in `localStorage` per user). `BuySellFunctionality` disables Buy (unless the ticker is short) when the total exceeds Available, and Sell (unless the ticker is long) when half the total does; both during a margin call. The server stays authoritative for flips.
- Deposit/Withdraw pages render `TransferForm` with `direction="deposit" | "withdraw"`: method tiles, per-method fields with format checks (Luhn, expiry, CVC, ABA routing checksum, email; helpers in `client/src/utils/payments.js`), and a `$` `QuantityStepper` (withdrawals capped at Available). Only `describeMethod`'s label and the amount are sent. Transactions merges `/transactions` and `/transfers` by date.
- Fractional orders: both trade forms have a `TradeModeToggle` (Shares | $) and an editable decimal `QuantityStepper` (6 decimals for shares, 2 for dollars). `toOrder` in `client/src/utils/orders.js` turns the input into `{ quantity, total }`: a dollar amount becomes `amount / price` shares, and on the portfolio an amount that covers the whole position closes it exactly.
- No prop-types and no `defaultProps`. React 19 ignores both on function components, so put defaults in the destructured parameters. Parameter defaults don't apply to `null`.

**Styling:** Bootstrap 4.6 is loaded from a CDN in `client/public/index.html`, plus custom classes in `client/src/App.css`. Tailwind v3 is also active, picked up automatically by CRA from `client/tailwind.config.js`; CRA 5 doesn't support Tailwind v4 or custom `postcss.config.js`. Preflight is disabled so Bootstrap keeps its base styles. Class names shared by both libraries (`mt-5`, `py-4`, `mr-2`, `shadow-lg`) resolve to Tailwind's values, because the bundled CSS loads after the CDN link.

## Repo notes

- Each rankings refresh (the first home page load in 30 minutes) costs 1 Alpha Vantage call plus 1 OpenAI call, plus 1 of each per candidate checked (usually 14 to 20, up to 30, fewer when their analyses are already cached), and takes tens of seconds. Each trading page load costs 1 Alpha Vantage call (2 when its analysis isn't cached) plus 1 OpenAI call when it isn't cached, each portfolio page load costs 1 Alpha Vantage call per open position, each full app load (the header's `/account`) costs 1 Alpha Vantage call per open position, each trade or withdrawal that adds risk costs 1 call per open short (for the collateral check), and each portfolio AI button costs 1 Alpha Vantage call plus 1 OpenAI call the first time it's opened. Latest prices are cached for 60s (shared by `/account` and `/portfolio`), and rankings and ticker analyses for 30 minutes; nothing else is, so this counts against the Alpha Vantage plan's rate limit (the free tier allows about 25 requests a day).
